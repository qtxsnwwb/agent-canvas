# Compare Two Sessions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A 对比 page that puts two sessions' numbers side by side — totals, by tool, by turn, files — entered from the session page's 「对比…」 picker.

**Architecture:** The server builds both sides from the summaries it already caches (the stats `SessionSummary` via `SessionSummaryCache.one()`, extended with a few fields, and the files service's per-session summary), pairs them, and answers one `GET /api/compare`. The web app adds a route, a picker dialog on the session page and the page itself; while either session is running the page refetches every 5 s.

**Tech Stack:** TypeScript, Fastify, React + Vite, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-24-compare-design.md` (binding; its 「决定」 items are rulings the user may overturn).

## Global Constraints

- Numbers use the stats page's definitions on the same summary: 总用时 = Σ `turnDurationMs(turn, now)` over the session's dated turns; 轮数 = dated turns; 工具调用 / 失败 = `calls.length` / failed calls (subagent-internal included); token = the three stats categories summed over turns and extras; a session with `usageNodes === 0` shows tokens as null (「—」).
- `SessionSummary` gains `nodeCount: number`, `subagentCount: number` (dispatch nodes: `kind === 'subagent'`), and per turn `promptNodeId: string | null` and `promptHead: string` (the prompt node's summary or title, whitespace collapsed, cut to 79 code points + `…` when longer than 80 — the ellipsis lets the page masker see a cut). Existing stats / files numbers and their tests must not change (extend, never edit, assertions).
- Limits: by tool `COMPARE_TOOLS_MAX = 30` rows then one 「其他」 row; by turn `COMPARE_TURNS_MAX = 50` (then a flag); files `COMPARE_FILES_MAX = 100` per group (then the remaining count). Tool names are paired literally (no cross-tool mapping).
- Files: paired by the path relative to each session's cwd (the files summary already gives `relativePath`; when null, the absolute path); a flag when the two cwds differ. Groups: both / only left / only right; within a group by (left + right touches) descending, then path.
- 「更好」 marking (bold) is computed on the page: shorter time, fewer calls, fewer failures, fewer new-input+output tokens; none when equal or either side is null.
- Masking on the page: session titles, prompt heads, file paths and cwds through the page's rule masker (the cross-session list masker, as the attention page uses); no learned values (spec 4).
- The exported viewer shows no 「对比…」 button (`SessionSource` gains nothing it would provide).
- Tests: invented data only, temp dirs, never port 4317, never the real `~/.claude/settings.json`, `~/.codex/hooks.json`, `~/.cursor/hooks.json`. Root commands: `npx --yes pnpm@10 typecheck`, `npx --yes pnpm@10 test`, `npx --yes pnpm@10 build`; one file `npx --yes pnpm@10 exec vitest run <path>`.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Do not push; do not open a PR.

## Review Focus

1. The same session compared with itself: every pair equal, nothing bold, the page says 「两边是同一个会话」. (Tasks 1, 2)
2. A Claude Code session against a Codex session: tool rows mostly one-sided, nothing crashes on a side with no turns or no token data. (Tasks 1, 2)
3. Two 100,000-node sessions: the endpoint answers from the caches (a second call re-reads nothing), first-call time stated; the browser never loads either graph. (Task 1)
4. Masking on: a key in a prompt head or a file path is masked on the page. (Task 2)
5. A running session on one side: numbers move within ~5 s; polling stops when both are idle and when the page is left. (Task 2)

### Task 1: Server — summaries and the compare endpoint

**Files:**

- Test: `packages/server/test/compare.test.ts`, `packages/server/test/api-compare.test.ts`, `packages/server/test/compare.timing.test.ts`; extend `stats-summary` tests for the new fields

**Interfaces:**
- Produces:
  ```ts
  // shared/src/compare.ts
  export const COMPARE_TOOLS_MAX = 30, COMPARE_TURNS_MAX = 50, COMPARE_FILES_MAX = 100;
  export interface CompareSide {
    sessionId: string; title: string; origin: Origin; projectId: string; cwd: string | null;
    status: SessionStatus; lastActivityAt: string;
    activeMs: number; turns: number; steps: number; toolCalls: number; failed: number; subagents: number;
    tokens: { input: number; cachedInput: number; output: number } | null;
  }
  export interface CompareToolRow { toolName: string; left: { calls: number; failed: number } | null; right: { calls: number; failed: number } | null }
  export interface CompareTurnRow {
    index: number;  // 1-based
    left: { promptNodeId: string | null; promptHead: string; activeMs: number; toolCalls: number; tokens: number | null } | null;
    right: /* same */ CompareTurnRow['left'];
  }
  export interface CompareFileRow { path: string; left: { reads: number; changes: number } | null; right: { reads: number; changes: number } | null }
  export interface CompareResponse {
    left: CompareSide | null; right: CompareSide | null;   // null: session not found
    sameSession: boolean;
    tools: CompareToolRow[]; otherTools: { left: number; right: number } | null;
    turns: CompareTurnRow[]; turnsTruncated: boolean;
    files: { both: CompareFileRow[]; onlyLeft: CompareFileRow[]; onlyRight: CompareFileRow[]; more: { both: number; onlyLeft: number; onlyRight: number }; cwdsDiffer: boolean };
  }
  // GET /api/compare?a=<sessionId>&b=<sessionId>  -> CompareResponse   (missing / repeated parameter -> 400)
  ```
  Turn `tokens` = new input + output of that turn (null for a no-token session). Session title by the shared `sessionName` rule.
