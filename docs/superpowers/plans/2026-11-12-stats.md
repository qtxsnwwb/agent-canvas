# Token Completion and Stats Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Give Codex sessions token usage, and add a stats page that answers cross-session questions (where time goes, slowest and most-failing tools, tokens, the three tools compared).

**Architecture:** Codex token usage comes from already-stored `token_usage_record` raw records in the Codex normalizer. Stats are computed from derived nodes only: a cached per-session summary, aggregated on request by a new `/api/stats` route, rendered by a new `#/stats` page with hand-written SVG charts.

**Tech Stack:** unchanged — TypeScript, pnpm workspace (`npx --yes pnpm@10 <cmd>`), Fastify, better-sqlite3, React, Vitest. No chart library.

**Spec:** `docs/superpowers/specs/2026-11-12-stats-design.md` (binding).

## Global Constraints

- Existing behaviour and tests stay unchanged, except: Codex nodes gain `usage` (Task 1) and the version pin.
- TDD for logic: failing test first. Vitest, node environment, no jsdom, no component tests.
- Tests use temp dirs only (`AGENT_CANVAS_PROJECTS_DIR`, `AGENT_CANVAS_DATA_DIR`, `AGENT_CANVAS_CODEX_DIR`, `AGENT_CANVAS_CURSOR_DB`); never read or write under the user's real home directory; the real service on port 4317 is not touched and its port not used.
- Fixtures are synthetic.
- The stats API returns no conversation content: counts, durations, names and ids only.
- User-facing text is Simplified Chinese, in the tone of the existing pages.
- Commits: English Conventional Commits ending with `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`. Do not push.
- Before each commit: `npx --yes pnpm@10 test`, `npx --yes pnpm@10 typecheck`, `npx --yes pnpm@10 build` all pass — read the actual pass/fail lines.
- Names fixed: shared types `StatsResponse`, `StatsRange = '7d' | '30d' | 'all'` in `packages/shared/src/stats.ts`; server module `packages/server/src/stats/{summary.ts,aggregate.ts,service.ts}`; route `GET /api/stats`; web page `packages/web/src/pages/Stats.tsx`, pure helpers in `packages/web/src/stats.ts`, route `#/stats`.

## Review Focus

1. A number on the stats page disagrees with what the session page shows for the same session (turn count, tool count, failures, tokens): definitions in spec section 4 must be applied identically.
2. Turns that span midnight, sessions partly inside the range, in-progress turns, stale "running" sessions, parallel tool calls, subagent-internal calls: each counted exactly as spec 4 says, none twice.
3. Codex token attribution: one response's usage counted once; unmatched records fall back or are dropped and counted, never duplicated on rebuild.
4. Large data (about 210,000 nodes): the first request must not block the service for long and must not be recomputed by concurrent requests; a changed session recomputes only its own summary.
5. Sources without data (Cursor tokens; an origin with no sessions in range): shown as "—" / absent, never as 0 that reads like a measurement.
