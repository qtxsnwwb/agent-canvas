# agent-canvas 里程碑 1（管线打通）实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 本地服务采集 Claude Code 的 transcript 和 hooks，归一成图并入库，通过 REST 和 WebSocket 提供；网页能浏览项目和会话，并以实时更新的列表显示某会话的节点。

**Architecture:** 两个事件源（JSONL 增量读取、hooks HTTP 端点）产出原始记录，先原样写入 SQLite 的 `raw_event`，再交给不做任何 IO 的 `Normalizer` 转成变更列表，由 store 在一个事务里写入派生表并分配全局序号 `seq`，最后经 WebSocket 推给前端。内容平面（JSONL）决定有哪些节点，状态平面（hooks）只改节点和会话的状态。

**Tech Stack:** Node ≥ 22，TypeScript，pnpm workspace，Fastify，better-sqlite3，chokidar，React + Vite，Vitest。

**Spec:** `docs/superpowers/specs/2026-11-10-agent-canvas-design.md`

**范围说明：** 规格有 6 个里程碑，每个里程碑一份计划。本计划只覆盖里程碑 1。画布（React Flow、elkjs）、四个视角、诊断页、hooks 安装命令不在本计划内。本计划的数据模型和接口是最终形态，后续里程碑只加视图。

## Global Constraints

- 服务只监听 `127.0.0.1`，默认端口 `4317`。
- 数据库位置 `~/.agent-canvas/data.db`，WAL 模式。环境变量 `AGENT_CANVAS_DATA_DIR` 覆盖目录。
- transcript 根目录 `~/.claude/projects`。环境变量 `AGENT_CANVAS_PROJECTS_DIR` 覆盖。所有测试必须用这两个变量指向临时目录，不得读写真实用户目录。
- hook 端点必须先应答 `200` 和空响应体，再做任何处理。
- 遇到不认识的记录类型或缺失字段不得抛出到管线外：未知类型计数，结构异常的对话记录派生为 `unknown` 节点。
- 原始记录原样保存；派生表必须能由 `raw_event` 完整重建。
- 测试夹具不得包含真实对话内容、真实路径或用户名。夹具由计划里给出的合成数据构成。
- 包名前缀 `@agent-canvas/`。所有包 `"type": "module"`，TypeScript `strict`。
- 提交信息用英文 Conventional Commits，结尾带 `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`。

## Review Focus

1. **按字节偏移读取时切在多字节字符中间。** transcript 里有大量中文。读取必须先在字节层面按 `\n` 切行，再整行解码；不能先解码再切。期望：中文内容原样还原，无乱码。（测试在 Task 3）
2. **单行极大。** 工具输出和内嵌图片能让一行达到数 MB。期望：读取分块进行不整文件载入；节点摘要截断到 200 字符；快照接口不返回完整内容。（测试在 Task 3、Task 4）
3. **首次全量导入阻塞 hook 端点。** 历史 transcript 可能有数百 MB，而 hook 超时只有 2 秒。期望：导入期间 `POST /hooks` 仍在 100 毫秒内应答。（测试在 Task 7）
4. **hook 载荷异常。** 非 JSON、空请求体、超大 `tool_response`、缺 `session_id`。期望：一律 `200` 空响应，不崩溃，载荷存入 `raw_event`。（测试在 Task 8）
5. **文件监听漏事件。** Windows 上文件系统事件不可靠，Claude Code 追加写入时可能不触发。期望：有定时全量扫描兜底，漏掉的追加在 5 秒内被读到。（测试在 Task 7）

export type RawEvent =
  | { source: 'transcript'; file: string; offset: number; line: string; recordType: string; sessionId: string; agentId: string | null }

export interface Store {

  getOffset(file: string): number;                      // 未记录时为 0

**Interfaces:**

```ts
// paths.ts
export type TranscriptFile =
  | { kind: 'session'; projectId: string; sessionId: string }
  | { kind: 'agent'; projectId: string; sessionId: string; agentId: string }
  | { kind: 'agent_meta'; projectId: string; sessionId: string; agentId: string }
  | { kind: 'title'; projectId: string; sessionId: string };
export function classifyPath(projectsDir: string, absPath: string): TranscriptFile | null;

// reader.ts
export interface ReadResult { lines: { offset: number; text: string }[]; newOffset: number; truncated: boolean }
export function readNewLines(absPath: string, fromOffset: number, maxBytes?: number): Promise<ReadResult>;
```

`classifyPath` 的映射（路径相对 `projectsDir`，同时接受 `/` 和 `\`）：

| 相对路径 | 结果 |
|---|---|
| `<p>/<s>.jsonl` | `session` |
| `<p>/<s>/subagents/agent-<a>.jsonl` | `agent` |
| `<p>/<s>/subagents/agent-<a>.meta.json` | `agent_meta` |
| `<p>/<s>/custom-title.json` | `title` |
| 其他（含 `tool-results/`、`*.prefix.json`） | `null` |

`readNewLines`：从 `fromOffset` 起以 64 KB 为块读取，在字节层面找 `\n`，每个完整行整体按 UTF-8 解码。`offset` 是该行首字节在文件中的位置，`newOffset` 是最后一个完整行之后的位置；末尾不以 `\n` 结束的部分不返回、不计入 `newOffset`。文件大小小于 `fromOffset` 时 `truncated` 为 `true`，并从 0 读起。`maxBytes`（默认 8 MB）限制一次调用读取的总字节数，到达后在最近的行边界停下，调用方再次调用继续；单行超过 `maxBytes` 时仍完整读出这一行。空行跳过。

`Normalizer` 在内存里为每个会话保存：当前 `Session`、节点表、工具节点的入参（Task 6 的权限匹配要用）、记录 `uuid` 到"该记录产生的最后一个节点 id"的映射、不产生节点的记录的 `uuid → parentUuid` 映射、每个 `agentId`（主线用空串）的当前 `turnId`。

**节点 id 规则（后续任务依赖）：**

| 节点 | id |
|---|---|
| 用户 prompt | 记录的 `uuid` |
| thinking、text | 记录的 `uuid` |
| tool、subagent | `tool:<tool_use_id>` |
| system、unknown | 记录的 `uuid` |

边 id 为 `<from>-><to>`。

**规则：**

1. 记录 `type` 不在 `user`、`assistant`、`system`、`attachment` 之内：不产生变更，返回 `unknownRecordType` 为该 `type`。`attachment` 不产生节点也不计为未知，只登记 `uuid → parentUuid`。
2. 会话首次出现时发 `session_upserted`：`status` 为 `idle`，`startedAt` 和 `lastActivityAt` 取记录 `timestamp`，`cwd`、`gitBranch` 取自记录。之后每条带 `timestamp` 的记录都更新 `lastActivityAt`；`cwd`、`gitBranch` 变化时更新；会话的 `projectId` 为 `'unknown'` 而 `apply` 的 `projectId` 参数不是时，更新为参数值。会话无变化时不重复发送。
3. `user` 记录，`message.content` 为字符串且 `isMeta` 不为 `true`：产生 `prompt` 节点，`title` 为 `'Prompt'`，`summary` 为文本摘要，`detail.text` 为全文。该 agent 的当前 `turnId` 设为 `promptId`，没有则用 `uuid`。会话状态置 `running`。`isMeta` 为 `true` 的不产生节点。
4. `assistant` 记录，取 `message.content[0]`：
   - `thinking`：`thinking` 节点，`title` 为 `'Thinking'`，`summary` 为思考文本摘要（可能为空串），`durationMs` 取 `thinkingDurationMs`。
   - `text`：`text` 节点，`title` 为 `'Text'`。
   - `tool_use`：若 `tool:<id>` 已存在（hook 先到），发 `node_updated` 把 `confirmed` 置 `true` 并补上 `summary`、`parentId`、`turnId`、`messageId`、`detail.input`，不改 `status`；否则发 `node_added`，`status` 为 `running`、`confirmed` 为 `true`。`name` 为 `Agent` 或 `Task` 时 `kind` 为 `subagent`，否则为 `tool`。`title` 和 `toolName` 为工具名，`summary` 为 `summarize(input)`。
   - 三种节点都带 `messageId`（`message.id`）和 `usage`（由 `message.usage.input_tokens`、`output_tokens` 映射；缺失为 `null`）。
   - `message.stop_reason` 为 `end_turn` 且记录不属于子代理时，会话状态置 `idle`。
5. `user` 记录，`message.content` 为数组：对每个 `tool_result` 块，向 `tool:<tool_use_id>` 发 `node_updated`：`status` 为 `is_error` 为真时 `failed`、否则 `succeeded`；`detail.output` 为块的 `content`；`summary` 保持为入参摘要不变。节点已是终态时不再发状态变更。目标节点不存在时忽略该块。
6. `system` 记录：`subtype` 为 `compact_boundary` 时产生 `system` 节点，`systemSubtype` 为 `'compact'`，`title` 为 `'Compact'`。其余 `subtype` 不产生节点，只登记 `uuid → parentUuid`。`compact_boundary` 这个取值未在本机实测到（抽查的会话没有发生压缩），在 Task 11 验收时用一个发生过压缩的真实会话核对；实测到的 `subtype` 只有 `stop_hook_summary`。
7. `parentId`：沿 `parentUuid` 向上找到第一个产生过节点的记录，取其最后一个节点 id；找不到为 `null`。`parentId` 非空时同时发一条 `sequence` 边。（并行批次的特殊规则在 Task 5。）
8. 记录是合法 JSON 但规则 3 到 6 中所需字段缺失或类型不符（例如 `assistant` 没有 `message.content`）：产生 `unknown` 节点，`title` 为 `'Unknown'`，`summary` 为原始行摘要，`detail.raw` 为解析后的记录。没有 `uuid` 的记录无法成为节点，按规则 1 计为未知类型 `<type>:malformed`。
9. 行不是合法 JSON：不产生变更，`unknownRecordType` 为 `'invalid-json'`。

`summarize`：字符串原样；其他值 `JSON.stringify`；把连续空白压成单个空格；超过 `SUMMARY_MAX` 时截到 `SUMMARY_MAX - 1` 个字符加 `…`。

**规则：**

1. **并行批次。** 批次是共享同一 `messageId` 的连续 `tool_use` 节点。批次里第二个及之后的工具节点，`parentId` 取批次第一个工具节点的 `parentId`（而不是前一个工具节点），连到它的边 `kind` 为 `fork`；当批次出现第二个成员时，把第一个成员的入边也补发一条 `fork` 边（id 为 `<from>-><to>:fork`）。批次之后第一个产生节点的非 `tool_result` 记录：`parentId` 为批次最后一个工具节点，并从批次内每个工具节点各发一条 `sequence` 边到它。
2. **子代理记录。** `agentId` 非空的记录按 Task 4 的规则处理，差别：节点的 `agentId` 为该值；`turnId` 为 `null`；不改会话状态；父链在该 agent 内部独立计算。
3. **`meta` 事件，`agentId` 非空（agent meta）。** `payload` 解析出 `toolUseId`、`agentType`、`description`、`finished`。向 `tool:<toolUseId>` 发 `node_updated`：`agentId` 为该 agent、`title` 为 `agentType`、`summary` 为 `description` 的摘要。记下 `agentId → tool:<toolUseId>`。
4. **派发边。** 当某 agent 的"派发节点"（规则 3）和"该 agent 的第一个节点"都已知时，发一条 `spawn` 边，并把第一个节点的 `parentId` 更新为派发节点。两者到达顺序不定，哪个后到哪个触发，且只发一次。
5. **`meta` 事件，`agentId` 为空（标题）。** `payload` 的 `customTitle` 写入会话 `title` 并发 `session_upserted`。会话尚不存在时先记下，等会话出现时带上。
6. `meta` 的 `payload` 不是合法 JSON 或缺字段：忽略，不产生变更。

| `SubagentStart` | 无（派发节点已由 `PreToolUse` 或 JSONL 建立） | 不变 |
| `SubagentStop` | 若已知 `agent_id` 的派发节点且其未到终态：置 `succeeded` | 不变 |
| `Notification` | 无 | `notification_type` 为 `permission_prompt` → `awaiting_permission`；`idle_prompt` → `awaiting_input`；其他不变 |
| `Stop`、`StopFailure` | 无 | `idle` |
| `PostCompact` | `node_added`：`system` 节点，id 为 `compact:<session_id>:<receivedAt>`；`systemSubtype: 'compact'`，`confirmed: false`，`title: 'Compact'`，`summary` 为 `compact_summary` 摘要 | 不变 |
| `SessionEnd` | 无 | `ended` |
| 其他事件名 | 无 | 不变；返回 `unknownRecordType: 'hook:<eventName>'` |

通用规则：

1. **终态不回退。** 节点 `status` 已在 `TERMINAL_STATUSES` 内时，任何 hook 都不再改它的 `status`（`durationMs` 为空时仍可补上）。
2. **内容平面优先。** Task 4 规则 5 的 `tool_result` 始终可以把非终态节点推到终态，包括 `awaiting_permission`。
3. 目标节点不存在的 `Post*`、`PermissionDenied`：忽略节点变更，会话状态照常更新。
4. `payload` 不是合法 JSON 或没有 `session_id`：不产生变更，`unknownRecordType` 为 `'hook:invalid'`。
5. hook 创建会话时（此前没有任何 JSONL 记录）：`cwd` 取 `payload.cwd`，`startedAt`、`lastActivityAt` 取 `receivedAt`，`projectId` 用 `apply` 的参数。
6. 每个 hook 都把会话 `lastActivityAt` 更新为 `receivedAt`。
7. `ended` 的会话收到 `SessionStart` 或 `UserPromptSubmit` 时可以回到 `idle` 或 `running`（会话恢复）；收到其他事件保持 `ended`。

export class Pipeline {
  constructor(store: Store, config: Config);
  onChanges(listener: (changes: SeqChange[]) => void): () => void;   // 返回取消订阅函数
  ingestFile(absPath: string): Promise<void>;                        // 读一个文件的新内容并处理
  ingestHook(eventName: string, sessionId: string | null, payload: string): void;
  scanAll(): Promise<void>;                                          // 遍历 projectsDir 下所有可识别文件并 ingestFile

**规则：**

1. `ingestFile`：`classifyPath` 为 `null` 则返回。`session`、`agent`：循环调用 `readNewLines(path, store.getOffset(path))` 直到没有新行；每一行解析出顶层 `type`（解析失败记为 `invalid-json`）后 `insertRaw`，返回 `null`（重复）的行跳过归一；其余交给 `Normalizer.apply`，变更交给 `store.applyChanges` 并通知监听者；`unknownRecordType` 交给 `store.bumpUnknown`；每轮循环后 `setOffset`。`sessionId` 和 `agentId` 取自路径而非记录内容。`truncated` 时照常处理（去重靠 `insertRaw`）。
2. `title`、`agent_meta`：整文件读出作为 `meta` 原始事件。内容与上次相同（按文件内容比较）则跳过。
3. 每轮 `readNewLines` 之间用 `setImmediate` 让出事件循环。同一文件的并发 `ingestFile` 调用串行化：已有一个在进行时，新调用等它结束后再跑一次，而不是并行读。
4. 会话状态水合：对某个会话调用 `Normalizer.apply` 之前，若 `normalizer.hasSession(id)` 为假且 `store.getSession(id)` 存在，先按 `store.rawForSession(id)` 的顺序重放进 normalizer 并丢弃产生的变更。
5. `rebuild`：`store.clearDerived()`，新建 `Normalizer`，对 `allSessionIdsInRaw()` 的每个会话按 `rawForSession` 顺序重放并 `applyChanges`。`projectId` 由事件的 `file` 经 `classifyPath` 得到；只有 hook 的会话用 `'unknown'`。
6. `ingestHook`：`insertRaw` 后同规则 1 的归一和广播。`projectId` 取已有会话的 `projectId`，会话不存在时用 `'unknown'`；之后 JSONL 记录到达时由 `session_upserted` 更正。
7. 源文件消失：`scanAll` 发现 `file_offset` 里记录的 `session` 文件已不存在时，对应会话发 `session_upserted`，`sourceDeleted: true`。
8. `startWatcher`：chokidar 监听 `projectsDir`（`ignoreInitial: true`，`depth: 3`），`add`/`change` 事件调用 `ingestFile`；启动时先 `scanAll()`，`ready` 在其完成后兑现；另起每 `rescanMs` 毫秒一次的定时器，对每个已知文件比较 `fs.stat` 的大小与 `file_offset.size`，不同则 `ingestFile`，并检查新出现的文件。

路由：

| 路由 | 行为 |
|---|---|
| `GET /api/projects` | `Project[]` |
| `GET /api/projects/:id/sessions` | `Session[]` |
| `GET /api/sessions/:id/graph` | `GraphSnapshot`；不存在 `404` |
| `GET /api/sessions/:id/nodes/:nodeId` | `NodeDetail`；不存在 `404` |
| `GET /api/diagnostics` | `Diagnostics`，`lastHookAt` 取自 `pipeline.lastHookAt()` |
| `POST /hooks` | 任意请求体。立即 `reply.code(200).send()`（空响应体），然后在 `setImmediate` 里调用 `pipeline.ingestHook`。`eventName` 取 `hook_event_name`，缺失为 `'unknown'`；`sessionId` 取 `session_id`，缺失为 `null`。请求体不是 JSON 时把原始文本作为 `payload`。 |
| `GET /ws` | WebSocket。收到 `subscribe`/`sessions`：之后推送所有 `session_upserted`。收到 `subscribe`/`session`：先发一条 `changes` 消息补齐 `store.changesSince(sinceSeq, sessionId)`（为空也不发），之后推送该会话的全部变更。同一连接可同时持有一个 sessions 订阅和一个 session 订阅，新的 session 订阅替换旧的。无法解析的消息忽略。 |
| 其他 `GET` | `config.webDist` 非空时提供静态文件，未命中的非 `/api` 路径回退到 `index.html`。 |

`POST /hooks` 的 `bodyLimit` 为 64 MB，并为该路由注册接受任意 `content-type` 的原始文本解析器，使解析失败不会产生 `4xx`。超过 `bodyLimit` 时仍返回 `200` 空响应并丢弃载荷。用 `@fastify/websocket` 和 `@fastify/static`。
