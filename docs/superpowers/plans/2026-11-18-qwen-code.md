# Qwen Code Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Read Qwen Code's session files — origin `qwen` — and show them with every existing feature, from the product's public source only.

**Architecture:** One `FileSource` (`QwenFileSource`) and one `AgentNormalizer` (`QwenNormalizer`), registered the way the DeepSeek / Buddy / Doubao ones were. The normaliser keeps, per thread, every valid record and the live chain (leaf = last physical conversation record, walked through `parentUuid`), derives nodes from the chain, and emits the difference — the model `GeminiNormalizer` uses, which already copes with nodes that disappear and earlier nodes changed by later records. The source reads with `readGuardedLines` and gives an archived file the key of its unarchived place.

**Tech Stack:** TypeScript (ESM, Node >= 22), better-sqlite3, chokidar, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-18-qwen-code-design.md` (binding). Format reference, binding for every field name and file layout: `docs/formats/qwen-code.md` ("reference x.y" below). Conventions the spec inherits: `docs/superpowers/specs/2026-11-17-more-sources-cn-design.md` section 10, items 2, 4, 5, 6, 21, 23.

## Global Constraints

- No test or manual run reads or writes anything under the real home directory or the real application-data directories (`~/.agent-canvas`, `~/.claude`, `~/.codex`, `~/.cursor`, `~/.gemini`, `~/.grok`, `~/.copilot`, `~/.dsh`, `~/.workbuddy`, `~/.workbuddy-ai`, `~/.codebuddy`, the Doubao directories, `~/.qwen`). Every test config names every tool directory (guard: `packages/server/test/no-real-tool-dirs.test.ts`); never port 4317.
- Fixtures are invented from the format reference. Fake secrets are concatenated at run time. Nothing is copied from a real session.
- Output for the existing ten origins does not change: `NORMALIZER_VERSION` stays 34, no schema change, the whole existing suite passes with no change to existing assertions (other than the origin lists this plan extends). Helpers exported from `normalize/gemini.ts` keep their behaviour.
- The tool directory is read-only for us. A missing `<qwenDir>/projects` starts no source, creates nothing, watches nothing.
- Lenient reading: an unknown subtype is skipped and counted through `unknownTypeName('qwen', …)`; a throwing normaliser is reported as `qwen:normalizer-error` as the existing ones do; nothing a single bad file does stops other sessions.
- Session ids are Qwen Code's own, bare. `KEY_PREFIXES.qwen = 'qwen:'` prefixes store keys only.
- Token usage follows `packages/shared/src/model.ts`: `inputTokens` = input not read from cache; `cachedInputTokens` = cache reads; `outputTokens` per spec 4.5.
- Anything whose result could depend on the order paths sort in must be decided another way and tested with both orders (Windows `\` and POSIX `/` sort differently around letters; batch 1 shipped such a bug to CI).
- No new runtime dependency. Label: `Qwen Code`.
- Root commands: `npx --yes pnpm@10 typecheck`, `npx --yes pnpm@10 test`, `npx --yes pnpm@10 build`; one file: `npx --yes pnpm@10 exec vitest run <path>`. Wall-clock bounds go in `*.timing.test.ts` and are multiplied by `AGENT_CANVAS_TIMING_SCALE` as `packages/server/test/pipeline.timing.test.ts` does.
- Commits end with `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`. Do not push; do not open a PR. Do not run `codex`, do not operate Cursor.

## Review Focus

1. Records arriving one line at a time versus all at once versus after a rebuild, with rewinds in between. Expected: identical graph, details, usage, title and status in all three (Tasks 2, 3).
2. A record that re-roots the chain far back in a long session, many times. Expected: abandoned nodes removed, cost not quadratic in the session length (Task 2 timing).
3. A file replaced in place (message-group deletion) or moved to `chats/archive/` and back. Expected: deleted content gone, nothing duplicated, the session never flagged as source-deleted by a move (Task 4).
4. A subagent file or its `.meta.json` read before the parent's `agent` call, or never accompanied by a `.meta.json`. Expected: linked when the link can be established by either rule, unlinked otherwise, never a phantom session (Task 3).
5. A very long single line (`chat_compression.compressedHistory`, `agent_bootstrap.history`, a multi-megabyte tool output). Expected: bounded memory, nothing of it kept in the normaliser beyond the record being applied, not rendered into node details where the spec says so (Tasks 2, 3).

  ```ts
  // qwen-chain.ts
  export interface ChainRecord { uuid: string; parentUuid: string | null; conversation: boolean }
  /**
   * The live chain of a thread, kept incrementally. `add` takes records in physical order (a repeated uuid is a
   * fragment: it does not move anything) and returns the uuids that left the chain and those that joined it, both in
   * chain order. Equal, after any sequence of adds, to: last physical conversation record, walked through parentUuid
   * until null, a missing parent (gap) or a cycle; reversed.
   */
  export class LiveChain {
    add(rec: ChainRecord): { removed: string[]; added: string[] };
    readonly chain: readonly string[];
    readonly gaps: number; readonly cycles: number;
  }
  // qwen-prompt.ts
  /** Reference 3.4 / spec 4.3. `images` = count of non-text parts kept. */
  export function promptText(rec: unknown): { text: string; images: number };
  export type UserKind = 'prompt' | 'mid-turn-prompt' | 'realtime-prompt' | 'mod-prompt' | 'notice' | 'hidden' | 'unknown';
  export function classifyUser(rec: unknown): UserKind; // spec 4.1
  // qwen-usage.ts
  /** Spec 4.5; authType null = unknown. Null when `usageMetadata` is not an object with a numeric count. */
  export function qwenUsage(usageMetadata: unknown, authType: string | null): Usage | null;
  // qwen.ts
  export class QwenNormalizer implements AgentNormalizer {}
  export function qwenNodeId(sessionId: string, agentId: string | null, uuid: string, part: string): string;
  ```
  Non-conversation subtypes (never a leaf, never a link): `session_artifact_event`, `session_artifact_snapshot`, `session_sources_snapshot`, every `managed_session_*`. A line is valid per spec section 4's first paragraph; a main-thread line whose `sessionId` differs from the event's session is skipped and counted. Same-uuid fragments merge per spec 4.1. Nodes are a function of the chain: when `add` reports removals the nodes of those records go with `node_removed`, including "Turn failed" / "Interrupted" nodes and usage; a tool result is folded into the record holding its call (spec 4.2) and re-emits that node, and leaves with its own record. Title per spec 7 from the last physical `custom_title` regardless of the chain (the sidecar title arrives in Task 3; first prompt as the last resort). Status per spec 8. Auth type for usage: nearest preceding `session_model` or user `executionContext.authType` on the chain. `chat_compression`: a system node with the two token counts; `compressedHistory` never enters a node detail. Node ids include the session id (a `/branch` copy repeats uuids). The normaliser holds no tool input or output text beyond the record being applied (details go to the store; follow how `GeminiNormalizer` / `BuddyNormalizer` release them). A restart of the file (a smaller offset than the last, as the other `'offset'`-identity normalisers detect it) resets the thread.
