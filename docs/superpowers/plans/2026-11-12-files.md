# File View Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** A by-file view: which files a session read or changed (with a jump to each step), and which sessions touched a given file.

**Architecture:** The three normalizers attach `files` (path + action) to tool nodes from structured tool inputs only. A cached per-session file summary feeds two routes; the session page gains a file panel and a deep link; a new `#/files` page lists files per project with the sessions that touched them.

**Tech Stack:** unchanged — TypeScript, pnpm workspace (`npx --yes pnpm@10 <cmd>`), Fastify, better-sqlite3, React, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-12-files-design.md` (binding).

## Global Constraints

- Existing behaviour and tests stay unchanged except: tool nodes gain `files` (Task 1) and the version pin.
- TDD for logic: failing test first. Vitest, node environment, no jsdom, no component tests.
- Tests use temp dirs only (`AGENT_CANVAS_PROJECTS_DIR`, `AGENT_CANVAS_DATA_DIR`, `AGENT_CANVAS_CODEX_DIR`, `AGENT_CANVAS_CURSOR_DB`); never read or write under the user's real home directory; the real service on port 4317 is not touched and its port not used.
- Fixtures are synthetic.
- File paths are never guessed from command lines (the one exception is the fixed `apply_patch` format). File contents are never stored.
- The new routes return paths, counts, times, names and ids only.
- User-facing text is Simplified Chinese, in the tone of the existing pages.
- Commits: English Conventional Commits ending with `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`. Do not push.
- Before each commit: `npx --yes pnpm@10 test`, `npx --yes pnpm@10 typecheck`, `npx --yes pnpm@10 build` all pass — read the actual pass/fail lines.
- Names fixed (already in `packages/shared/src/model.ts`): `GraphNode.files?: FileTouch[]`, `GraphNode.filesTruncated?: boolean`, `FileTouch { path, action }`, `FileAction = 'read' | 'edit' | 'write' | 'delete'`, `MAX_FILES_PER_NODE = 50`. Further: path helpers in `packages/shared/src/paths.ts` (`normalizeFilePath(raw, cwd)`, `relativeToDir(path, dir)`, `samePath(a, b)`), response types in `packages/shared/src/files.ts` (`SessionFilesResponse`, `ProjectFilesResponse`); server module `packages/server/src/files/`; routes `GET /api/sessions/:id/files`, `GET /api/files`; web `packages/web/src/pages/Files.tsx`, session panel `packages/web/src/canvas/FilePanel.tsx`, pure helpers `packages/web/src/files.ts`; hash routes `#/files` and `#/s/<id>/f/<encoded path>`.

## Review Focus

1. Path identity: the same file written as `D:\a\b.ts`, `d:/a/b.ts`, `D:/a/./x/../b.ts`, or relative to the session's working directory is one file; on Windows comparison ignores case, on POSIX it does not; a path outside the working directory is shown in full.
2. No double counting: Codex `apply_patch` plus the `FileChange` item of the same call; the same file named twice in one call; a record applied twice; rebuild equals live.
3. A truncated or malformed `apply_patch` body, a non-string or empty path field, more than 50 files in one call: no crash, nothing invented, the truncation flag set.
4. Counts on the file views agree with the nodes: every (path, action) on a node is counted once per node; subagent-internal touches belong to the session.
5. Large data (about 120,000 tool calls, 45,000 file touches): the first request does not block the service for long; a changed session recomputes only its own summary; the list is bounded (200 files per response).
