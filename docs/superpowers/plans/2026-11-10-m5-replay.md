# agent-canvas 里程碑 5（复盘）实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 新增"复盘"视角：底部时间轴，拖动或播放时画布只显示该时刻之前的节点及它们当时的状态，节点上叠加耗时和 token 用量；首页可以按关键词检索历史会话。

**Architecture:** 状态回放不依赖变更日志（它有上限且重建时清空），而是让每个工具/子代理节点记下自己的结束时间 `endedAt`，由纯函数 `graphAt(graph, t)` 从当前图推出 t 时刻的图，再交给已有的 `buildView` 和布局。检索是服务端一个新的只读接口，用 SQLite 对会话字段和提示节点摘要做子串匹配。

**Tech Stack:** 无新增依赖。

**Spec:** `docs/superpowers/specs/2026-11-10-agent-canvas-design.md`（7.3 的"复盘"一行、12 节第 5 项）。本计划给规格第 6 节增加一个接口 `GET /api/search`、给 4.2 增加字段 `endedAt`，Task 1、Task 2 同步改规格。

**已核实的数据事实（2026-11-10，本机真实数据，只统计结构）：** 11945 个工具节点里只有 429 个带 `durationMs`（它目前只来自 hooks），所以历史会话几乎没有耗时；token 用量挂在一条助手消息拆出的每个节点上（同一 `messageId` 的节点带同一份用量），直接相加会重复计数。

## Global Constraints

- 里程碑 2–4 计划的 Global Constraints 继续适用，但本里程碑**允许**改 `packages/server`（Task 1、Task 2）。
- 派生数据必须能由 `raw_event` 重建：`endedAt` 只能取自事件本身（transcript 记录的 `timestamp`、hook 的接收时间），按原始事件顺序重放结果相同。
- 回放是只读的：不得修改实时图，退出复盘后画布回到实时状态且不丢更新。
- token 合计一律按 `messageId` 去重。
- 检索接口不返回节点详情，片段只来自会话字段和提示摘要（不超过 200 字符的那份）。

## Review Focus

1. **回放时刻落在节点执行中途。** 期望：开始时间 ≤ t 且（没有 `endedAt` 或 `endedAt` > t）的工具显示为"执行中"，不显示耗时；t 之后才出现的节点和连到它们的边都不显示。（测试在 Task 3）
2. **时间戳异常。** `timestamp` 或 `endedAt` 无法解析、`endedAt` 早于 `timestamp`（时钟回拨、hook 与 transcript 时间不一致）。期望：无法解析的开始时间按 0 处理（始终可见）；`endedAt` 早于开始时间时按开始时间处理，耗时为 0，不出现负数。（测试在 Task 1、Task 3）
3. **拖动时间轴的开销。** 7000 多个节点的会话里连续拖动。期望：`graphAt` 线性复杂度，未受影响的节点保持同一个对象引用（否则每一帧都全量重渲染）；重建受已有节流控制。（测试在 Task 3）
4. **检索词里的特殊字符。** `%`、`_`、反斜杠、引号、超长字符串、只有空白。期望：按字面匹配，不报错，不构成 SQL 注入；少于 2 个非空白字符返回空结果；超过 200 字符截断。（测试在 Task 2）
5. **token 重复计数。** 一条助手消息拆成"思考 + 回复 + 3 个工具"五个节点，各带同一份用量。期望：合计只算一次。（测试在 Task 3）

**Interfaces:**
- Produces:

```ts
// shared/api.ts
export type SearchField = 'title' | 'id' | 'branch' | 'cwd' | 'prompt';
export interface SearchMatch { field: SearchField; nodeId: string | null; snippet: string }   // nodeId 仅 prompt 有值
export interface SearchHit { session: Session; matches: SearchMatch[] }                        // 每个会话最多 3 条 matches
export const SEARCH_MIN_CHARS = 2;
export const SEARCH_MAX_CHARS = 200;
export const SEARCH_SNIPPET_CHARS = 80;

// store
searchSessions(query: string, limit: number): SearchHit[];
// REST
// GET /api/search?q=<文本>&limit=<1..100，默认 30> → SearchHit[]，按 session.lastActivityAt 降序
```

规则：`q` 去掉首尾空白，超过 `SEARCH_MAX_CHARS` 截断；少于 `SEARCH_MIN_CHARS` 返回 `[]`。不区分大小写的子串匹配（`LIKE ... ESCAPE '\'`，`%`、`_`、`\` 转义后按字面匹配），匹配对象：会话的 `title`、`id`、`gitBranch`、`cwd`，以及该会话主线 `prompt` 节点的 `summary`。`matches` 顺序：会话字段在前（title、id、branch、cwd），提示在后（按时间升序），共最多 3 条。`snippet`：匹配位置前后共不超过 `SEARCH_SNIPPET_CHARS` 个字符，被截断的一侧加 `…`。`limit` 非法时用默认值，超出范围夹到 1..100。

为提示检索建部分索引（启动时 `CREATE INDEX IF NOT EXISTS`）：`CREATE INDEX IF NOT EXISTS node_prompt ON node (session_id) WHERE json_extract(body, '$.kind') = 'prompt'`，查询条件原样带上这个表达式以命中索引。

### Task 3: 回放的纯函数

**Files:**

- Test: `packages/web/test/canvas-replay.test.ts`

**Interfaces:**
- Produces:

```ts
export interface ReplayRange { startMs: number; endMs: number }
/** 所有节点（含子代理内部）的最早开始时间 .. 最晚的开始或结束时间；空图为 null；无法解析的时间忽略。 */
export function replayRange(graph: Graph): ReplayRange | null;
/**
 * t 时刻的图：保留开始时间 ≤ t 的节点（开始时间无法解析的始终保留）和两端都保留的边。
 * 工具/子代理节点：endedAt 能解析且 max(endedAt, 开始时间) ≤ t → 原样（终态）；
 * 有 endedAt 但 > t → status 改为 'running'、durationMs 和 endedAt 置空；
 * 没有 endedAt → 原样（它此刻的真实状态）。
 * 没有变化的节点返回同一个对象引用；整张图没有任何变化时返回传入的 graph 本身。
 */
export function graphAt(graph: Graph, tMs: number): Graph;
/** 主线 prompt 节点的时间点，升序。 */
export function turnMarks(graph: Graph): { turnId: string; ms: number }[];
/** 按 messageId 去重求和；messageId 为空的节点各算一次；usage 为空的跳过。 */
export function usageTotal(nodes: Iterable<GraphNode>): Usage;
/** 999 → "999"，1200 → "1.2k"，15000 → "15k"，1250000 → "1.3M"；负数或非有限数 → "0"。 */
export function formatTokens(n: number): string;
```

模型行为：`setMode('replay')` 时把回放时刻设为范围末尾；replay 视角下每次重建用 `graphAt(live.getGraph(), timeMs)` 代替实时图喂给 `buildView`；实时更新仍然累积在 live 里（范围末尾随之延长），但回放时刻不动；切回其他视角后画布立即反映最新的实时图。`totals` 统计 `graphAt` 结果里的全部节点（含子代理内部）。

界面：
- 视角切换增加第四项 `复盘`。进入后页面底部出现时间轴条（高 64 px，画布相应让出高度）：播放/暂停按钮、倍速选择（`1×`、`10×`、`60×`，默认 `10×`）、滑块（`<input type="range">`，范围 = `range`，步长 1000 ms）、当前时刻（本地时间，精确到秒）与"第 N / M 轮"、"回到末尾"按钮、右侧合计"N 个节点 · 输入 X · 输出 Y"（`formatTokens`）。滑块上方画出各轮次的刻度线，点击刻度跳到该时刻。
- 播放：每 100 ms 把时刻推进 `100 ms × 倍速`，到末尾自动暂停；拖动滑块时暂停播放。组件卸载或离开复盘视角时清除定时器。
- 复盘视角下的节点叠加一行：工具/子代理显示 `耗时 3.4s · 输入 1.2k · 输出 340`（没有的项省略；全没有则显示 `—`），回复节点显示 token 两项。回放中"执行中"的节点照常有脉冲动效。
- 跟随：复盘视角下跟随回放图里的最新节点；使用者拖动画布后停止跟随，规则不变。
- 抽屉在复盘视角下照常可用（显示的是节点当前的完整内容），头部多一行灰字"内容为当前状态，不随时间轴回退"。
