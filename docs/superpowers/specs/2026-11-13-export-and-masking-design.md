# 导出分享与敏感信息遮蔽 设计规格

- 日期：2026-11-13
- 状态：已评审通过并实现；2026-11-13 已在本机真实数据上核对（见 7.1）
- 前置：主规格 `2026-11-10-agent-canvas-design.md`。本文只写新增和改动的部分。

## 1. 目标

1. **导出**：把一个会话导出成一个文件发给别人看——同事、工单、文档。两种格式：自包含的 HTML（只读的会话页）和 Markdown（线性文字记录）。
2. **遮蔽**：导出时把密钥之类的敏感信息替换掉；页面上也有一个开关，投屏、截图时打开。

### 成功标准

- 导出的 HTML 文件双击就能在浏览器里打开，不装任何东西、不联网，能看到概览画布、瀑布图和每一步的详情。
- 导出的 Markdown 能直接贴进文档或 PR，在常见的渲染器里结构正确。
- 导出前能看到“找到了几处敏感信息、各是什么类型”；导出文件里看不到这些值。
- 页面上的遮蔽开关打开后，页面上来自会话的文字里看不到这些值。
- 数据库不变；不需要重建；检索仍按原文匹配。

### 不做

- 入库时遮蔽；修改或删除数据库里的原文。
- 上传、生成分享链接、任何联网行为。
- 导入别人导出的文件。
- PDF、图片导出。
- 识别人名、地址、电话等一般个人信息；“看起来随机的长字符串”的猜测（见第 2 节）。

### 必须对用户说清的限制

遮蔽是尽力而为，**不保证遮全**：没见过格式的密钥、写在句子里的密码、图片里的内容都可能漏掉。导出对话框和导出文件里都写明“分享前请自己再看一遍”。

|---|---|---|---|

| 赋值形式（名字含 password / secret / token / api key 的变量后面的值） | 10,250 | 2,333 | 28 |

## 3. 遮蔽

### 3.1 规则

共享包里的纯函数（`packages/shared/src/masking.ts`），服务端导出和页面显示共用同一份。四个类别（`MaskCategory`）：

| 类别 | 内容 | 导出默认 | 页面开关 |
|---|---|---|---|
| `credential` 固定格式的凭据 | 见下表 | 开 | 遮 |
| `assignment` 赋值形式 | 名字是密钥名（3.2）的变量、键、命令行参数的**值**（`KEY=v`、`KEY: v`、`"key": "v"`、`--key v`、`--key=v`，值可带引号）；见 3.2 的筛选 | 开 | 遮 |
| `personal` 个人信息 | 邮箱地址；主目录路径里的用户名（`C:\Users\<名>`、`/Users/<名>`、`/home/<名>` → 名字换成 `~`；Windows 形式不分大小写，两种斜杠和 JSON 转义的双反斜杠都认），用户名取自会话的工作目录和服务所在机器的用户名 | 关 | 不遮 |
| `custom` 自定义词 | 用户列出的词，原样匹配（不分 ASCII 大小写），每个 3–200 个字符，最多 100 个，不含控制字符和不可见的格式字符；互相重叠的命中合并成一处 | 有词就开 | 遮 |

固定格式的凭据和其他密钥规则（类型名 `MaskType` 和中文名）：

| 类型 | 中文名 | 形式 |
|---|---|---|
| `openai-key` / `anthropic-key` | OpenAI key / Anthropic key | `sk-` 后 ≥ 20 个 `[A-Za-z0-9_-]`；`sk-ant-` 开头的是 Anthropic |
| `stripe-key` | Stripe key | `sk_live_`、`sk_test_`、`rk_live_`、`rk_test_`、`whsec_` 后 ≥ 16 个字母数字 |
| `github-token` | GitHub token | `ghp_` / `gho_` / `ghu_` / `ghs_` / `ghr_` 后 ≥ 30 个字母数字；`github_pat_` 后 ≥ 22 个 |
| `gitlab-token` | GitLab token | `glpat-` 后 ≥ 20 个 |
| `huggingface-token` | Hugging Face token | `hf_` 后 ≥ 30 个字母数字 |
| `google-oauth` | Google OAuth 令牌 | 访问令牌 `ya29.` 后 ≥ 20 个；刷新令牌 `1//` 后 ≥ 20 个（前面是 `/` 或 `:` 的不算，那是网址） |
| `aws-key` | AWS key | `AKIA` / `ASIA` 后正好 16 个 `[A-Z0-9]` |
| `aws-secret-key` | AWS secret key | `aws_secret_access_key` / `secretAccessKey` / `SecretAccessKey` 等名字后正好 40 个 base64 字符；或同一行里 AWS key 之后 300 个字符内、正好 40 个 base64 字符且大写、小写、数字都有的一段 |
| `azure-key` | Azure 存储密钥 | 连接串里 `AccountKey=` / `SharedAccessKey=` 的值（≥ 8 个 base64 字符） |
| `google-key` | Google API key | `AIza` 后正好 35 个 |
| `slack-token` | Slack token | `xox[abprse]-` 后 ≥ 10 个 |
| `npm-token` | npm token | `npm_` 后正好 36 个字母数字 |
| `jwt` | JWT | `eyJ…` 三段 base64url，前两段各 ≥ 10，且前两段都能解码成 JSON 对象（超过 16 KB 的段不解码，按 JWT 处理） |
| `bearer` | Bearer 令牌 | `Bearer ` 后的令牌（≥ 8 个，含数字或大小写混合） |
| `authorization` | Authorization 凭据 | `Authorization: Basic <base64 ≥ 16 个，含数字或大小写混合>`；`Authorization: Token|Bot <≥ 8 个，含数字或大小写混合>` |
| `private-key` | 私钥 | PEM 私钥块整块，从 BEGIN 到对应的 END；没有 END 就到文字末尾 |
| `url-password` | 网址里的密码 | `scheme://user:password@host` 里的密码（到 authority 里最后一个 `@` 为止，密码里可有 `@`、`#`、`:`、百分号转义）；没有冒号时像令牌的 userinfo（`https://<令牌>@host`，≥ 8 个且含数字或大小写混合）整段 |
| `cli-password` | 命令行密码 | `-u|--user user:pass` 的密码部分——用户不是纯数字（`docker run -u 1000:1000` 是 uid:gid），密码 ≥ 4 个且不像路径（`rsync -u host:/path`）；`mysql|mariadb|mysqldump|mysqladmin … -p<pass>` / `--password=<pass>` |
| `netrc-password` | .netrc 密码 | `password <值>`，前面 300 个字符内有 `machine` 或 `login` |
| `cli-password`（续） | 命令行密码 | `docker login … -p <pass>` / `--password <pass>` / `--password=<pass>`（不含 `--password-stdin`）；`sshpass -p <pass>` |
| `sql-password` | SQL 密码 | `IDENTIFIED BY '…'`、`[WITH] PASSWORD '…'`（单引号或双引号；值是 `${…}` 等引用时不算） |
| `cookie` | Cookie | `Cookie:` 头里每个 cookie 的值；`Set-Cookie:` 头里第一对的值（名字和属性保留） |

另有 `assignment` 密钥/密码、`email` 邮箱、`home-user` 用户名、`custom` 自定义词、`failed` 处理失败。

**开头位置（紧贴规则）**：凭据在任何位置开始都认——前面是 JSON 转义（`\n`、`\t`、`\"`、`\uXXXX`）、百分号转义（`%0A`）、`_`、`-`、空白或其他符号都算“干净的开头”。前面**紧贴一个字母或数字**时，正文必须像随机串才算：

| 规则 | 紧贴字母或数字时的要求 |
|---|---|
| `sk-` | 正文 ≥ 32 个，同时含数字、大写、小写 |
| Stripe | 正文 ≥ 24 个，至少两个数字，大写、小写都有 |
| GitHub `gh?_`、GitLab、Slack、AWS | 正文含数字 |
| Hugging Face | 正文大写、小写都有 |
| Google OAuth | 正文同时含数字、大写、小写 |
| GitHub `github_pat_`、Google API key、npm、JWT | 无额外要求（前缀独特，长度固定或有结构） |

所以 `task-…`、`risk-assessment-…`、`desk-top`、`risk_test_CalculatesValueAtRisk1.py` 这类词不会被当成密钥；这条规则在截断模式下同样适用。

### 3.2 赋值形式

**密钥名**：名字（不分大小写，去掉非字母数字后）含 `password`、`passwd`、`passphrase`、`secret`、`token`、`apikey`、`accesskey`、`privatekey`、`accountkey`、`credential`、`authorization`、`cookie`，或某一段（按 `_`、`-`、`.` 和驼峰切开）**正好**是 `auth` 或 `pass`（`db_pass`、`PASS`；不含 `passport`、`compass`）。`pwd` 不是密钥名（环境变量 `PWD` / `OLDPWD` 是目录）。其中含 `password`、`passwd`、`passphrase`、`secret`、`privatekey` 或段 `pass` 的是**密码类**。

**计数类名字**（与模型 token 数量有关，不是密钥名）是一个封闭清单，按去掉大小写和分隔符后整名比较：`tokens`、`token_count`、`token_counts`、`num_tokens`、`n_tokens`、`max_tokens`、`max_output_tokens`、`max_input_tokens`、`max_completion_tokens`、`min_tokens`、`total_tokens`、`input_tokens`、`output_tokens`、`prompt_tokens`、`completion_tokens`、`reasoning_tokens`、`cached_tokens`、`cached_input_tokens`、`cache_read_input_tokens`、`cache_creation_input_tokens`、`tokens_used`、`tokens_per_second`、`token_limit`、`token_usage`、`token_type`、`tokenizer`、`tokenize`、`tokenized`、`tokenization`、`tokenizer_name`。这些名字下数字、布尔值、模型名、编码名不遮；只有长而随机的字符串（≥ 16 个，同时含数字、大写、小写）照遮。其他含 `token` 的名字都是密钥名（`refresh_tokens`、`access_tokens`、`apiTokens`、`token_store`、`id_token`、`csrf_token`……）。`Cookie:` 头由 cookie 规则处理，不按赋值形式。

值满足下面任一条就**不遮**：

- 空；
- 是变量引用或模板：`$VAR`、`${…}`、`$(…)`、`{{…`、`<…`、`%VAR%`（`$` 后面跟数字或后面还有 `$` 的不算引用，所以 `$2b$…`、`$argon2id$…` 这类哈希要遮）；
- 是明显的占位符：全是同一个字符、只有 `x` / `*` 和分隔符、`your-…`、含 `changeme` / `example` / `placeholder`、或正好是 `null`、`undefined`、`true`、`false`、`none`、`nil`、`empty`、`redacted`、`hidden`；
- 含 `${…}` 模板（`` `Bearer ${token}` ``、`` `prefix-${value}` ``）；
- 是日期、CSS 颜色（`#ff00aa12`）、或一句话（至少三个由字母组成的词、最多一个数字，如 `At least 8 characters`）。

除此之外，**带引号**的值（或结构化数据里的字符串）跟在**密码类**名字后面的，不论大小写和数字一律遮——这一条在路径判断**之前**（`password: "P@ss/word1"`、`"secretAccessKey": "…/…"` 都遮；i18n 文件里 `"login.password": "Password"` 在原处会被遮；它不会被学，别处的 “Password” 不受影响）。其余的值满足下面任一条就不遮：

- 是路径：以 `/`、`./`、`../`、`~`、`\\` 或盘符（`C:\`、`D:/`）开头，或由名字段（字母、数字、`.`、`_`、`-`、`@`）用 `/`、`\` 连成且最后一段有扩展名或至少三段；20 个字符以上、只由 base64 字符组成、同时含大写、小写、数字的值**从不**算路径（`wJalrXUtnFEMI/K7MDENG/…` 是密钥候选）；
- 短于 8 个字符；
- 形如 `process.env.X`、`os.environ[…]`、`config.api.key`（标识符加点或括号），或是函数调用（`getToken(`）；但有一段超过 24 个字符、或 16 个字符以上且同时含大写、小写、数字时不算（`DISCORD_TOKEN=MTIz….GhIjKl.AbCd…` 要遮）；
- 不带引号、不含数字的标识符（`TokenType`、`response`）；
- 不含数字也不同时含大小写字母。

结构化数据（对象）里，键名是密钥名时：字符串值按带引号的值处理；数字换成占位符；数组和嵌套对象里的每个字符串和数字都遮；`true` / `false` / `null` 保留。

### 3.3 替换形式

- 命中的值替换成 `‹已遮蔽·<类型的中文名>#<n>›`，例如 `‹已遮蔽·OpenAI key#1›`、`‹已遮蔽·邮箱#3›`。
- 编号在**一次导出**（或页面上的一个会话）里按“类型 + 值”分配：同一个值编号相同，读的人能看出两处是同一个值。编号按首次出现的顺序（导出：按阅读顺序）。同一类型的不同值超过 10 万个后，新值不再编号（报告 `numberingCapped`）。
- 主目录用户名直接换成 `~`，不编号。
- 多条规则命中重叠的范围时取最先开始、其次最长、再次按类别（凭据 > 赋值 > 自定义词 > 个人信息）的那一条；被盖住一部分、但伸出去的那一条，伸出去的部分也遮（任何规则命中的字符都会被遮）。替换后的文字不再参与匹配；原文里的 `‹›` 不处理。
- **截断的文字**：只用于可能被截断的文字——共享包的判断函数 `isCutSummary`（摘要：长度到了 200 个字符，或以 `…` / `...` 结尾）和 `isCutTitle`（标题：60 个码点以上，或以 `…` / `...` 结尾；三种来源的规整器都把首个提示的前 60 个码点作为会话标题，且不加省略号）。导出里，可能被截断、且正是某个最早的主线提示（按规整器的方式折叠空白）开头的会话标题，**按完整的提示先遮蔽再截断**到 60 个码点，不截在占位符中间；其他标题按截断模式遮蔽；文件名取自遮蔽后的标题。节点摘要由输入或文本得出的，按遮蔽后的输入或文本重新得出；其余摘要按 `isCutSummary` 决定是否截断模式。截断模式只放宽**末尾**：
  - 一个干净开头（紧贴规则照常适用）的凭据前缀，后面至少 4 个字符一直到末尾（`…` 之前），虽然短到无法确认也遮（`sk-proj-ab12…`、`ghp_ab12…`）；文字中间的任何东西不放宽；
  - 密码类名字后面一直到末尾的值，不论形状都遮；其他名字照常筛选（`{"token":"abc…` 不遮）；
  - 末尾至少 3 个字符是某个自定义词的开头（不分 ASCII 大小写）时遮；代价：一个恰好是自定义词开头的普通词出现在被截断文字的最末尾时也会被遮；
  - 末尾至少 6 个字符是某个学到的值的开头时遮，类型同那个值；
  - 截断模式下认出的东西**一律不学**。
- **两遍遮蔽**（导出用；页面可选）：第一遍扫描范围内的全部文字，记下密钥规则找到的值（只留在内存里的遮蔽器中）；第二遍除规则外，这些值原样出现的每一处也遮，类型和编号与第一次认出时相同。学什么：
  - 固定格式的凭据（上表 `openai-key` 到 `jwt`、`private-key`、`google-oauth`）一律学；
  - 其他规则（赋值、`bearer`、`authorization`、`azure-key`、`url-password`、`cli-password`、`netrc-password`、`cookie`）找到的值，只有通过强度门槛才学：≥ 12 个字符、不含空白、含数字、小写 / 大写 / 数字 / 符号中至少两类、不像路径、不是网址（只由字母和符号组成的值——单词拼起来的——一律不学）；没通过的仍在原处遮蔽；
  - 截断模式下认出的、重叠后剩下的片段不学；值长 8–512 个字符；最多学 20 万个（超出时报告 `learnedCapped`，导出开头有提示）。
  - 查找学到的值：按前 8 个字符的哈希分桶，桶里每个值都完整比较（不会因为共享前缀的值太多而漏）；一段文字里比较的字符总数超过文字长度的 32 倍加 100 万时（只有专门针对学到的值构造的文字才会到），这段文字停止查找学到的值，只按规则遮蔽，计入报告 `learnedSkipped`，导出开头有提示。不整段遮住，是为了不让一段特殊文字毁掉整段内容；规则本身仍然全部生效。
- 遮蔽函数出错时这段文字整体换成 `‹已遮蔽·处理失败›`（计入报告）。
- 函数：`createMasker(options) → { mask(text, { truncated? }), maskValue(value), maskWithSpans(text, { truncated?, key?, nested? }), learn(text, { truncated? }), learnValue(value), adopt(values), learnedValues(), learnedCount(), wouldMask(text, { truncated? }), report() }`；另有 `isCutTitle`、`isCutSummary`、`cutMaskedText`、`maskWarnings`、`isPathLike`。`maskWithSpans` 返回遮蔽后的文字和每处替换在原文和遮蔽后文字里的位置；`adopt` 把别处学到的值（类型 + 值）放进遮蔽器。`wouldMask` 只判断会不会遮，不计数、不占编号、不学。`MaskReport` 是每个类型的处数和不同值的个数，**不含值本身**，另有 `numberingCapped`、`learnedCapped`、`learnedSkipped`。

**已知漏遮**（遮蔽是尽力而为，分享前请自己再看一遍）：

- 不带引号、全是小写字母、不含数字的密码（`PASSWORD=correcthorse`）；
- 由几个普通单词组成的口令（`"correct horse battery staple"`，被当成一句话）；
- 被截断在前几个字符内的密钥（`sk-a…`、`ghp_ab…`，前缀后不足 4 个字符；露出的部分没有用处）；
- 紧贴在字母或数字后面、正文不够随机的密钥（如紧贴单词的 `sk-` + 全小写十六进制）；
- 没有固定前缀、也不在密钥名后面的令牌（Discord 等各种无前缀令牌、随机 id 形式的密钥）；
- 经过 base64、百分号编码或其他编码的密钥（编码后的形式没有可识别的前缀）；
- 图片、PDF 等二进制内容里的文字；
- 学到的值超过 20 万个、或查找被工作量上限中止的文字里，别处原样出现的值（导出开头会提示）；
- `-u` 后的纯数字用户名、不带引号的路径形式密码（`PASSWORD=/a/b/c.txt`），`.netrc` 以外格式的配置文件里不在密钥名后面的密码；
- 文字（而不是结构化数据）里 JSON 对象嵌在密钥名下面时，对象里面的值（`"apiTokens": {"a": "…"}`；结构化的输入输出里会遮）；
- 同一行里先出现 AWS secret、后出现 AWS key 时的裸 secret（只向后找）；
- 不是会话中最早 20 个主线提示开头、却被截断在 60 个码点的会话标题里，前缀后不足 4 个字符的密钥（按截断模式，见上）；
- 页面上（开关打开时）：服务端第一遍学到的值超过上限或扫描超过 10 秒时，后面的值只在原处遮蔽（见第 5 节）。

### 3.4 作用的文字

节点的标题、工具名、摘要、详情里的输入、输出、文本；会话标题、工作目录、分支；文件路径；检索片段。结构化的输入输出（对象）逐个值处理，键名也当文字遮蔽（键名同时用于判断赋值形式，见 3.2）；`__proto__` 之类的键作为普通数据保留。导出里由输入或文本得出的摘要，按遮蔽后的输入或文本重新得出；其他摘要和标题照常遮蔽，被截断的（3.3）按截断模式。

### 3.5 性能

单条文字上限按现有详情的大小（几 MB）考虑：所有规则在线性时间内完成，不使用会灾难性回溯的写法；自定义词用 Aho–Corasick，与词的个数和长度无关；学到的值的查找有工作量上限（3.3）。实现时用 1 MB 的最坏输入测量并给出上限。

## 4. 导出

### 4.1 入口和对话框

会话页工具栏新增“导出”按钮，打开对话框：

- **格式**：HTML / Markdown。
- **范围**：整个会话 / 只导出当前选中的这一轮（没有选中轮次时该项不可选）。
- **内容**：包含思考（默认是）；包含子代理内部的步骤（默认是）；工具输出：每步前 8 KB（默认）/ 全部 / 不含。
- **遮蔽**：四个类别的开关（默认见 3.1），自定义词的编辑入口。
- **扫描结果**：按当前选项扫描一遍，列出每个类型找到几处、几个不同的值（只有类型和数量）。选项变化时重新扫描。
- **预计大小**。超过 `EXPORT_MAX_BYTES`（50 MB）时不允许导出，提示缩小范围或减少输出。
- 一行提示：遮蔽不保证完整，分享前请自己再看一遍。
- “导出”按钮：浏览器下载文件，文件名 `agent-canvas-<会话标题的安全形式>-<日期>.html|md`。

对话框的选项（不含自定义词）记在浏览器里；自定义词存在服务端的本机设置里（数据目录下的设置文件，与通知设置同样的方式）。

### 4.2 接口

- `POST /api/sessions/:id/export/preview`，请求体是导出选项 → `{ report: MaskReport, estimatedBytes, nodeCount, tooLarge }`。
- `POST /api/sessions/:id/export`，同样的请求体 → 文件内容（`Content-Disposition: attachment`）。超过上限返回 413。
- `GET|PUT /api/export/settings` → 自定义词列表。
- `POST /api/sessions/:id/mask/learned`，请求体 `{ categories }`（只能是 `credential`、`assignment`、`custom` 的子集；`custom` 接受但不学）→ `{ values: { type, value }[], capped }`：整个会话的第一遍学习结果（与导出的第一遍相同），供页面的遮蔽开关预先装入（见第 5 节）。按会话缓存，会话有变化时作废；学到上限或超过 10 秒时停下，`capped: true`。它返回的是密钥的值：与导出接口一样要求同源 `Origin` 和 JSON，`Cache-Control: no-store`，不写日志；它没有比节点详情接口给同一页面更多的东西，只是集中。
- 实际返回的状态码：导出和预览 200、400（选项不合法；错误信息不回显请求里的字段名或值）、403（不是本页面的 JSON 请求）、404（会话不存在）、409（要求按自定义词遮蔽而设置文件损坏）、413（超过大小上限；请求体超过 1 MB 时由框架返回）、429（同时进行的导出和预览超过 4 个）、499（客户端已离开，实际不会被收到）、500（导出失败）、501（只有导出 HTML：查看器模板缺失或占位符不是正好一处）；设置 200、400、403；已学值 200、400、403、404。
- 与其他接口一样只接受来自回环地址的请求；导出接口是唯一会把会话全文成批送出的接口，因此用 POST 并校验 `Origin`，避免别的网页用一个链接触发下载。
- 导出在服务端流式生成，分批读节点详情，不把整个会话的详情同时放进内存；生成期间让出事件循环。

### 4.3 导出的数据

- 范围内的节点和边（“只导出这一轮”时：该轮主线的节点、它派出的子代理及其内部节点、相关的边）；不含子代理内部步骤时，去掉 `agentId` 非空的节点，保留派发节点。
- 每个节点的详情遮蔽后再按选项裁剪（输出按 UTF-8 字节截断在字符边界上，不截在占位符中间，截断处标明原始大小）。
- 会话信息：标题、来源、开始和最后活动时间、工作目录、分支（遮蔽后）；项目 id 由遮蔽后的工作目录重新编码得出。
- 导出信息：工具名和版本、导出时间、范围和内容选项、遮蔽报告（类型和数量）。
- 字段按**白名单**导出（`packages/server/src/export/assemble.ts` 的 `*_FIELD_POLICY`，类型上穷举：新加字段不表态就编译不过）：文字字段遮蔽；枚举、布尔、数字、时间、用量按固定集合或格式重建；各种 id 原样保留，但遮蔽器在其中找到任何东西的 id（用 `wouldMask` 检查，不计数、不占编号）换成一致的别名 `masked-id-<n>`（边、详情、轮次跟着换；编号跳过范围内已有的真实 id，别名不会与真实 id 相同）。
- 不导出：原始记录（详情的 `raw` 一律为 `null`）、节点的 `inputKey`（未加盐的完整输入哈希，可用来验证被遮的值）、hook 载荷、其他会话的任何数据、统计、异常列表、本机路径以外的环境信息。
- 要求按自定义词遮蔽而自定义词的设置文件读不了时，预览和导出都拒绝（409），不在没有自定义词的情况下导出。

### 4.4 HTML

- 一个自包含文件：内联的脚本和样式、内嵌的数据，没有任何外部引用；带一条内容安全策略（`default-src 'none'`，只允许内联的脚本和样式、`data:` 图片），打开时不发任何网络请求。
- 内容是只读的会话页：概览画布、逐步等视角、瀑布图、详情抽屉、回放。没有文件面板和异常面板（导出数据里没有它们需要的汇总），没有首页、检索、统计、异常、通知、诊断、导出按钮，没有实时更新。顶部有一条说明：这是 Agent Canvas 导出的只读快照、导出时间、遮蔽了哪几类各几处、“内容可能仍含敏感信息”。
- 实现方式：网页现有代码的第二个构建入口（查看器），数据层从内嵌数据读取，不访问接口；构建产物是一个 HTML 模板，服务端导出时把数据填进去。数据内嵌在 `<script type="application/json">` 里，并转义 `<`、`>`、`&`、U+2028、U+2029，使数据里的任何内容都不能结束脚本块或被当成标记。
- 查看器只把数据当文字渲染（与现有页面一样不用 `dangerouslySetInnerHTML`）；数据里的链接不渲染成可点击的外部链接。
- 模板随 npm 包一起发布（打包脚本检查它存在）。

### 4.5 Markdown

- 开头：会话标题、来源、时间、导出信息和遮蔽说明。
- 按轮次分节：提示（引用块）、回复、思考（折叠块 `<details>`，默认收起）、每一步工具调用（工具名、状态、耗时；输入和输出各一个代码块）。子代理的步骤缩进在派出它的那一步下面的 `<details>` 里。
- 会话里的文字一律写成代码，从不当 Markdown：多行的（提示、回复、思考、系统说明、输入、输出）放在围栏代码块里（提示在引用块里），单行的（标题、工具名、表头字段、id）放在行内代码里；这是 CommonMark、GFM 自动链接、数学公式扩展都不会解释的唯一形式。代码块的围栏、行内代码的分隔符都比内容里最长的反引号串多一个，保证内容不会提前结束；代码之外只有本工具写的固定文字。双向控制字符换成 U+FFFD。
- 截断的输出标明“（已截断，原始 N KB）”。

## 5. 页面上的遮蔽开关

- 顶栏新增“遮蔽”开关，状态记在浏览器里（`localStorage`），默认关。打开时顶栏有明显的标识。
- 打开后，页面上所有来自会话的文字在渲染前经过同一个遮蔽函数（类别 `credential`、`assignment`、`custom`；`personal` 不遮）：首页的会话标题和检索片段、会话页的卡片摘要和详情抽屉、瀑布图、文件面板和文件页的路径、统计页的命令摘要、异常页的路径。
- 编号以页面上的一个会话为范围；跨会话的列表（首页、检索、统计）里不编号，只显示 `‹已遮蔽·类型›`。
- 检索仍按原文匹配。检索片段由**服务端**遮蔽：页面在开关打开时给 `GET /api/search`、`GET /api/search/content`（以及诊断页的 `GET /api/diagnostics`）加 `mask=1`。服务端用不编号的遮蔽器（`credential`、`assignment`、`custom`；自定义词设置损坏时片段整体换成 `‹已遮蔽›`）遮蔽命中所在的**完整**原文（内容检索：命中所在的那一段索引文字，最多 64 KB，结构化值带上它的键名；会话检索：标题、分支、工作目录或完整的提示），把命中位置映射到遮蔽后的文字，再从遮蔽后的文字里截出片段，不截在占位符中间；命中落在被遮蔽的值里时，`match` 就是那个占位符。返回的形状不变，另加 `masked: true`；不带参数时与原来逐字节相同。其他接口返回的会话文字是完整字段（路径、工具名、标题），由页面自己遮蔽；会话标题按 `isCutTitle` 判断是否截断。
- 页面在会话页打开开关时调用 `POST /api/sessions/:id/mask/learned`，用 `adopt` 把整个会话第一遍学到的值装入自己的遮蔽器，所以一个只在没打开的详情里认出的值，在别处出现时也遮住。
- 复制、详情里的“原始记录”视图同样遮蔽（开关打开时页面上没有任何途径看到原文）。
- 自定义词从服务端设置读取。
- 这个开关只影响这一个浏览器的显示，不影响数据库、接口返回的内容和通知。除带 `mask=1` 的检索和诊断外，接口仍返回原文——开关防的是屏幕上被看到，不是防本机上的其他程序、浏览器的开发者工具或地址栏（开关打开之前打开的地址仍含原始的 id）。遮蔽的范围和漏遮与导出相同（第 3 节），已学值的扫描有上限（`capped`）。

## 6. 错误处理

- 某个节点的详情损坏（无法解码）：导出里这一步标明“详情已损坏”，继续导出其余部分。
- 导出过程中会话有新内容：导出的是开始时的快照范围；文件头部的时间说明这一点。
- 遮蔽函数对某段文字抛错（不应发生）：这段文字整体替换为 `‹已遮蔽·处理失败›`，宁可多遮，不输出原文；计入报告。
- 设置文件损坏：读设置时按没有自定义词处理，并在对话框里提示；此时要求按自定义词遮蔽的预览和导出被拒绝（409），不会在缺词的情况下导出。

## 7. 测试

- 遮蔽：每种类型的正例和反例；赋值筛选的每一条；重叠命中；同值同号；替换后不再匹配；对象里按键名判断；超长输入的耗时上限；带特殊字符的自定义词；大小写；多字节字符边界。
- 导出数据：范围（整个会话 / 一轮，含子代理）；内容选项的每一项；输出截断在字符边界；损坏的详情；大小上限和 413。
- HTML：数据转义（数据里含 `</script>`、`<!--`、U+2028）；文件里没有外部引用；内容安全策略存在；用无头浏览器打开一个导出文件，断言没有任何网络请求、能看到轮次卡片和一步的详情。
- Markdown：围栏长度；内容里含三个以上反引号、HTML 标签、`</details>`；子代理的嵌套；截断标记。
- 接口：参数校验、`Origin` 校验、404、设置的读写。
- 页面：遮蔽开关作用到的每一处用纯函数覆盖（模型层面）；检索高亮落在占位符上。
- 真实数据：用本机数据数出每个类型遮蔽了几处、几个不同的值（只看数量），写进本文；挑一个中等大小的会话各导出一次 HTML 和 Markdown，核对文件大小、节点数，并用同一套规则对导出文件再扫一遍——固定格式的凭据应为 0 处。不查看内容。

### 7.1 真实数据核对（2026-11-13）

这次改动不改数据库格式，不需要重建。只看数量、类型、大小和耗时，不看内容；导出的文件核对后立即删除。

- 预览了全部 40 个会话（默认选项：凭据和赋值两类开）：36 个可以整个导出，4 个 Cursor 会话（2.4 万到 3.9 万步）因超过 50 MB 只能按轮导出；最慢的一次预览 6.3 秒。
- 可导出的会话里共遮蔽 6,692 处：赋值形式 5,616 处，其余为固定格式的凭据——Google OAuth 令牌 240、Cookie 230、`.netrc` 密码 157、命令行密码 94、网址里的密码 72、Bearer 71、OpenAI key 62、JWT 41、SQL 密码 41、私钥 12，另有 AWS、Anthropic、GitHub、Google API、Stripe、Azure、GitLab、Hugging Face、npm 各 1–10 处。
- 导出一个 5,544 步的 Codex 会话：Markdown 13.4 MB、2.3 秒；HTML 22.3 MB、2.8 秒（其中查看器 2.0 MB）。响应头带 `attachment`、`nosniff`、`no-store`。HTML 的内嵌数据里没有 `inputKey`，所有详情的 `raw` 为空，数据之外没有任何外部引用，带内容安全策略。
- 对导出的数据按导出时的方式（逐个字符串）用同一套规则重扫：固定格式的凭据 **0 处**；凭据加赋值两类也是 0 处（HTML）。把整个文件当成一段文字重扫会得到几十处“命中”，逐一分类后全部是已遮蔽的占位符与相邻的键名、标点被拼在一起造成的假象；Markdown 里另有 2 处长 12、其中 7 个是标点的赋值候选，是排版产生的，不是密钥。
- 页面用的两个接口：`mask/learned` 在上述会话上 0.75 秒（94 个值），在最大的会话上 2.9 秒（46 个值），都没有触到上限；带 `mask=1` 的内容检索 78–257 毫秒，返回的每条片段都带 `masked` 标记，重扫片段没有发现凭据。
- 防护：不带 `Origin` 的设置写入和来自其他来源的预览请求都返回 403。
