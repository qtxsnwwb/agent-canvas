# 时间线视角：时间都花在哪个子代理上了

状态：已实现，0.4.0 发布
日期：2026-11-24

## 1. 目的

一个会话花的时间比预想的长很多时，用户最想先弄清的是**时间都花在哪个子代理上了**。这个视角把主线和所有子代理放在同一条时间轴上，给每条线程两个数字，并按“主线等它的时间”排名。

这是用户挑的五个新方向里的第二个（第一个“待处理”页已合并；其余是用量预算、书签批注、两会话对比）。

### 1.1 现有的东西

- 画布下方的“执行过程”面板（瀑布图，`packages/web/src/canvas/waterfall.ts`）：**一个轮次或一个子代理**里的每一步一行，同一条时间轴，能看并行。它看细节，不看全会话。
- “复盘”视角：按时间回放到某一时刻，用于“当时发生了什么”，不用于比较各段长短。

新视角与它们互补：看全会话、按线程、按时间归属排名。

### 1.2 不做的

- 跨会话的排名（“所有会话里最耗时的子代理”）。以后统计页要做时再说。
- 按钱算：用量只按 token 显示，与统计页一致。
- 改服务端：不加接口、不改数据库。

### 1.3 反目标

- 数字加起来对不上：同一分钟被算给两条线程，或总数超过会话的实际用时。
- 并行的子代理被“各自用时”排在前面，掩盖了真正拖住主线的那一个（所以默认按等待时间排）。

## 2. 做法

| 做法 | 说明 | 结论 |
|---|---|---|
| A. 网页里现算 | 会话页已在浏览器里持有整张图（每一步的开始、结束、所属子代理、派出关系），新写纯计算模块算出线程区间和时间归属，新加一个视角画出来；图更新时重算，进行中的处理复用执行过程面板的时钟规则 | **选用** |
| B. 服务端算，新接口 | 以后可复用于跨会话排名；但要新接口和重算推送，网页手上已有全部数据，等于做两遍 | 不用 |
| C. 执行过程面板加“全会话”模式 | 复用时间轴画法；但面板矮窄，放不下十几个嵌套的子代理，行的含义从“步骤”变成“线程”会和面板现有的点选、高亮、跟随搅在一起 | 不用（画法可以借，不放进面板） |

## 3. 定义

“线程”：主线（`agentId === null` 的节点），或一个子代理（同一个 `agentId` 的节点）。子代理由主线或另一个子代理里的派出节点（`kind === 'subagent'`，`childAgentId` 指向它）派出。

每一步的起止沿用执行过程面板的规则（`buildWaterfall`）：工具和子代理节点从 `timestamp` 到 `endedAt`（或 `timestamp + durationMs`；进行中的到“现在”）；思考节点在记录时间之前持续它的时长；其余是瞬时标记。“现在”按 `waterfallClock`：主线只在会话运行或等批准时走动；子代理和派出节点在会话未结束且最近 5 分钟有活动时也走动；导出的快照用 `snapshotClock`。

### 3.1 “拦住上级”的区间（用户决定：网页端按工具区分）

“上级在等某个子代理”不能一律用派出节点的区间表示。审读查实各工具的记法不同：

| 情况 | 拦住上级的区间 |
|---|---|
| Claude Code 前台派出、Gemini、Qwen Code、WorkBuddy、CodeBuddy 及其余来源 | 派出节点的区间（工具结果在子代理干完时才回来） |
| Claude Code 后台派出、以及任何“派出后上级接着干别的”的情况 | 从派出到上级开始这条消息之外的下一步为止（包括又派出另一个子代理）；此后上级如果一直没有动作、直到这个子代理结束才接着动（被它结束的通知叫醒），这段空等也拦住上级。 |
| Codex 的派出（`spawn_agent`，以及追加任务的 `followup_task` / `send_message`） | 无。派出是一瞬间 |
| Codex 的 `wait_agent` 调用 | 这次调用的区间，拦住上级的是它所等的那几个子代理（参数里点名的，怎么认见下段）；同时等几个时按 3.3 取结束最晚的 |

是不是后台，不从输入里读（节点摘要截在 200 字，`run_in_background` 常被截掉）：看行为。派出节点拦住上级，直到上级开始一个不属于同一条消息的步骤（同一 `messageId`；没有消息 id 的来源用同一 `parentId` 的兄弟节点，Grok 每个节点接在前一个后面，没有这种标记）；前台派出在结果回来之前上级没有新步骤，所以拦住整段。上级接着干活之后，如果在子代理结束之前它已停下、到子代理结束后才有下一步，从它停下到子代理结束算在等这个子代理（不延长这一轮）。Codex 的 `wait_agent` 等的是参数里点名的子代理（按 id、派出时的任务名或路径认）；只认和本线程在同一棵派出关系里的子代理（主线那一棵，或某个找不到派出它的一步的子代理那一棵），本线程自己除外；点名的都不在这一棵里时不算等。点名认不出时，等当时在干活的、本线程派出或追加过任务的子代理。

（3.1 表中后台一行和上面这一段，由用户于 2026-11-24 修订（用户决定）：原来的写法是“后台派出不拦住上级，后台标记从输入里读”。以后某个工具换了记法，在这张表里补规则。）

派出节点没有结束时间、又不在进行中（个别来源）：按它派出的子代理最后一步的结束时间算；子代理也不知道时就当瞬时。

### 3.2 总用时（用户决定）

每一轮从提问的时间，到这一轮“主线最后一个不是派出节点的步骤”结束，或这一轮里拦住主线的区间结束，取较晚的；这一轮还在进行时到“现在”。各轮的区间**取并集**，不重复计算（后台子代理会让两轮的区间重叠）。两轮之间用户思考、离开的时间不算。总用时 = 并集的长度。

轮次结束之后后台子代理还在跑的时间不算进任何人的等待时间（那时用户没在等它），但照常画出横条，也计入它的“各自用时”。

### 3.3 两个数字（用户决定：两个都显示，默认按等待时间排）

**各自用时**（用户决定）：按每次派出分段。一段从这次派出开始，到下一次派出同一个子代理之前它的最后一步结束（没有下一次派出时，到它的最后一步结束）；各段的跨度相加。一个子代理仍占一行，横条分段画，鼠标提示列出派出了几次。只派出一次的子代理，各自用时就是它从派出到最后一步的跨度。并行的子代理各算各的，加起来可以超过总用时。

**主线等它的时间**：在总用时覆盖的每一刻，确定这一刻“归谁”：

1. 主线这一刻有正在进行的、不是派出节点也不是 `wait_agent` 的步骤，或这一刻不在任何拦住主线的区间（3.1）里：归**主线自己**。
2. 否则主线在等：这一刻拦住主线的那几个子代理里，**自己结束得最晚的那个**是拦住主线的（看子代理什么时候结束，不看它的区间在哪儿被截断；还在跑的按“现在”；并列时取 id 小的）。归这个子代理——
3. ——除非它这一刻也在等它自己派出的子代理：对它重复 1、2，一直往下，归到最深的那一个。

于是每一刻恰好归一条线程。所有子代理的“等待时间”加上主线自己的时间，正好等于总用时；这一点是要测试的不变量。

### 3.3a 来源的差别

- 豆包（用户决定）：同一轮里所有步骤记的是同一个时刻，没有可用的时间。豆包会话的时间线只显示“这个来源没有记录每一步的时间，无法生成时间线”。
- Grok 有子代理，照常处理。

### 3.4 主线的两个数字

主线一行显示“自己干活的时间”（按 3.3 归给主线的部分）和“等子代理的时间”（其余部分）。

### 3.5 进行中

进行中的线程横条延伸到“现在”，标“进行中”，数字随时钟更新（时钟走动时每秒一次，与执行过程面板相同）。

### 3.6 派出节点对不上的情况（审读意见，我的决定）

- 派出节点的 `childAgentId` 为空（Copilot 的并行子代理、Qwen / DeepSeek / WorkBuddy 里没配上的、Gemini 回退后、Claude 元数据还没到）：画一行，标“未配上”，它承接这个派出节点的等待时间，各自用时按派出节点自身的区间。
- 有线程但找不到派出它的节点：和主线派出的子代理排在同一层，鼠标提示写“找不到派出它的一步”，等待时间为 0。
- 防环和重复上级，沿用 `buildView` 的做法。
- 概览里轮次卡片的“历时”算到最后一步的开始，时间线算到最后一步的结束，两者会差一点；手册说明。

## 4. 视角

在会话页右上角的视角切换里（概览、逐步、拓扑、因果、复盘）加“时间线”。切过去，画布区域换成下面的视图；执行过程面板保留。

```
会话：重构导出模块                 总用时 2 小时 05 分 · 3 轮
排序：[等待时间] 开始时间                         等待    各自用时
  主线          ███░░░░░░░░░░░░░██░░░░░░░██       自己 18 分 · 等 1 小时 47 分
  实现者 #2       ██████████████████              55 分    55 分   ← 最长
    探索 #1         ████                          12 分    12 分
  评审 #2                         ████████        23 分    23 分
  评审 #1                   ██████                19 分    19 分
  实现者 #1       ████████████                     0 分    42 分
              |-----------|-----------|----//----|
             10:00       10:40       11:20      14:05
```

- 每条线程一行；嵌套的子代理缩进在派出它的线程下面。排序只在同一层的兄弟之间进行，默认按等待时间从多到少，可以切成按开始时间。
- 横条画线程的跨度；线程在等自己的子代理的那段画成浅色（主线上浅色的就是在等）。
- 右边两列是“等待”和“各自用时”；等待时间最多的那条标出来。
- 鼠标移到一行上，显示：派出它的那一步、开始和结束时间、步骤数（跟着精简 / 完整）、token（输入 / 输出 / 缓存，同一条消息拆成的多个节点只计一次，与复盘视角相同）。
- 点子代理那一行：执行过程面板切到这个子代理的步骤（与在画布上点子代理节点相同）。点主线横条上的某一处：面板切到那一刻所在的轮次。
- 时间轴：两轮之间超过 5 分钟、且这段时间里没有任何线程在活动的空白，压缩成一个断开记号（`//`），使一个开了一天的会话的横条不至于细得看不见；有后台子代理在跑的空白不压缩，免得截断它的横条。（我的决定，按审读意见收紧。）
- 子代理的名字沿用画布上子代理节点的标题；同名的按出现顺序加 #1、#2。
- 没有子代理的会话只画主线，并说明“这个会话没有派出子代理”。
- 来源的差别见第 3.3a 节。
- 遮蔽开关照常：子代理标题按页面遮蔽规则处理。

## 5. 计算的位置与代价

- 纯计算模块放在 `packages/web/src/canvas/`，输入整张图和时钟，输出线程树和每条线程的两个数字、横条区间、浅色区间；不依赖 React。
- 图更新时重算，与执行过程面板一样节流。算法须是线性的（按时间排一次序之后扫描）。在 10 万节点的会话上量；单次超过 50 毫秒就放进后台线程，像画布布局那样（`layout.worker.ts`）。
- 导出的 HTML 查看器与会话页共用 `SessionCanvas`，所以也有时间线，用快照时钟。查看器的内容安全策略不允许后台线程（见 `viewer/inThreadLayout.ts`）：计算模块不能自己按网址加载后台线程；需要后台线程时经 `SessionSource` 注入，查看器里在主线程算。
- 不论“精简 / 完整”开关，都在整张图上算。
- 视角的选择作为页面状态，不加进 `ViewMode`（它驱动 `buildView` 和布局）。执行过程面板目前只在“概览”里出现、范围来自画布选中；时间线需要自己的面板范围状态，并规定文件面板、异常面板的跳转和 `#/s/<id>/n/<node>` 深链接在时间线里的行为（打开该节点所在的子代理或轮次）。`canvas/Timeline.tsx` 已被复盘的时间轴占用，新组件另起名字。（审读意见，我的决定。）

## 6. 测试

只用自造数据。

| 要证明的事 | 做法 |
|---|---|
| 不变量 | 随机生成的会话（多轮、并行、嵌套、后台派出、进行中、缺结束时间）上，各线程等待时间之和 + 主线自己的时间 = 总用时；每一刻只归一条线程 |
| 归属规则 | 3.3 的每一条各一例：主线自己在干活时不算等；并行时归结束最晚的；并列取 id 小的；嵌套归到最深 |
| 按工具区分 | 3.1 表里每一行各一例：Claude 前台、Claude 后台（主线接着干活时等待为 0、派出节点开到子代理结束；主线停下闲着、被它结束的通知叫醒时，那段空等算它的）、Codex 派出（等待为 0）、Codex `wait_agent`（等一个、等几个）、读不到后台标记时按前台 |
| 总用时 | 两轮之间的空白不算；进行中的一轮算到“现在”；后台子代理使两轮区间重叠时不重复计算；轮次结束后后台还在跑的时间不算等待 |
| 各自用时 | 并行的子代理各算各的，可以超过总用时；被派出多次的子代理按段相加，段间的空闲不算 |
| 豆包 | 显示“无法生成时间线” |
| 时钟 | 会话停下后进行中的横条不再变长；快照用快照时钟 |
| 缺数据 | 派出节点没有结束时间；子代理还没有任何步骤；时间读不出来的步骤 |
| 视角 | 切换、排序、缩进、标出最长、点行联动执行过程面板、断开记号、没有子代理时的说明、遮蔽 |
| 性能 | 10 万节点的会话，单次计算的耗时（放在 `timing` 项目） |
| 现有视角不变 | 现有视角和执行过程面板的测试不改地通过 |
