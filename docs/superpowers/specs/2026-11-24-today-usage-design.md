# 今天用了多少：随时可见的今日用量和一条自设的提醒线

状态：设计中
日期：2026-11-24

## 1. 目的

用户同时用好几个编码代理，想**对“今天用了多少”心里有数**（用户原话）。不是管钱，也不是盯各家订阅的额度。现在要知道今天用了多少，得点进统计页、选 7 天、看最后一根柱子，还要自己把三类 token 加起来；“消耗异常高”只看单独一轮，不累计一天。

这是用户挑的五个新方向里的第三个（前两个是待处理页、子代理时间线；其余是书签批注、两会话对比，各自另行设计）。

### 1.1 目标

- 每个页面顶栏都有一个“今天”的小数字，瞥一眼就知道今天用了多少；点它看今天的明细。
- 数字看得懂：主数字是**新输入 + 输出**的 token；缓存读取单独列。再配今天的轮数和工作时长（有的工具没有 token）。
- 能和平时比：旁边写过去 7 天同一时刻平均用到多少。
- 用户可以设一条线（用户选的方案 B）：今天的主数字越过这条线时，发一次桌面通知，顶栏的数字变色；当天不再重复。不设线就不提醒。
- 数字和统计页完全一致（用户选的做法 A）。

### 1.2 不做的

- 不算钱，不接各家价格。
- 不对接各家订阅额度或它们自己的时间窗口（例如 5 小时窗口、每周上限）。
- 不按项目、按工具、按周分别设线；只有一条“今天、所有工具合计”的线。
- 不新增 token 数据来源：Cursor、豆包本来没有 token，Copilot CLI 只在会话退出时记总数，这里照实显示。

### 1.3 反目标

- 顶栏的“今天”和统计页的今天对不上。
- 越线后反复通知，或者服务重启、重新导入、重建数据库后又通知一遍。
- 为了算这个数字让采集或页面变慢（正在跑的大会话被反复整份重读）。

## 2. 做法的选择

| 做法 | 怎么算 | 取舍 |
|---|---|---|
| **A. 复用统计页的会话摘要（用户选的）** | 统计页已为每个会话算好一份摘要（轮次、token、时间，会话有变化时自动标记过期）。“今天”= 今天有动静的会话的摘要按统计页的规则加起来；有变化时最多每 30 秒重算一次，推到页面；越线判断在服务端 | 数字和统计页同一套代码，各家 token 的特殊规则不重写；代价是最多晚 30 秒左右，正在跑的会话要按节流重读 |
| B. 采集时边进边累加 | 每进来一个节点，把它的 token 加到今天的计数上 | 实时、便宜；但等于另写一套计数，各家规则重做一遍，容易和统计页对不上；重启、重新导入、过零点都要重算 |
| C. 只在网页里算 | 页面定时拉统计接口自己加 | 页面关着就提醒不了，不符合“提醒” |

用户选 A：晚 30 秒不影响“心里有数”，两个数字对不上会让人不再信这个数。

## 3. 口径

### 3.1 “今天”

- 服务所在机器的本地日期，从零点算起，和统计页的“天”一样（`localDayKey`）。
- 和统计页一样，**一轮算在它开始的那一天**：跨过零点的一轮全部算在昨天，它在今天的工作时长和 token 都不算今天的。会话退出时才记总数的那类记录（Copilot CLI 的 `session.shutdown`，统计页的 extra）按它自己的时间算。
- 时间读不出的轮次和记录不算（统计页同样不算）。
- 过零点后“今天”从零开始，越线状态也从头开始。

### 3.2 数字

全部按统计页的定义（`StatsMeasures`），范围是今天、所有来源、所有项目：

- **主数字** = 新输入 + 输出（token）。这是顶栏显示的数，也是提醒线比的数。
- 缓存读取：单独一行，不计入主数字。原因：在 Claude Code 等工具里它常占输入的九成以上，而它比新输入便宜得多，加进去主数字会大得没有意义。
- 轮数、工作时长（统计页的 activeMs：进行中的轮算到现在，最后一次活动 15 分钟后停止增长）。
- 按来源拆开：每个今天有轮次的来源一行，各自的主数字、缓存读取、轮数、工作时长；没有 token 数据的来源（Cursor、豆包）token 列写“—”。
- 一个来源“有没有 token 数据”按统计页的判断：看**全部**已采集的数据，不只看今天或最近 8 天（实现时的决定：和统计页一致是反目标里写明的）。所以 Copilot CLI 今天的会话还没退出时，它这一行写 0，不写“—”，并注明“退出时才记总数”。
- 一个来源都没有 token 数据时，主数字写“—”，提醒线不起作用（页面上说明原因）。

### 3.3 和平时比

- “过去 7 天同一时刻平均” = 昨天起往前 7 个本地日里，每天**在当天同一时刻（精确到分钟）之前开始的轮次**的主数字之和，取平均（7 天都算，没用的日子算 0）。现在 10:45，就和过去 7 天每天 10:45 之前的用量比，避免拿半天比一整天。这个时刻和区块标题里的“截至”是同一个（实现时的决定）。
- 只用来对照，不参与提醒。
- 过去 7 天都没有 token 数据时不显示这一行。

## 4. 页面

### 4.1 顶栏

所有页面顶栏，“待处理”旁边多一项：

```
待处理 3   今天 1.2M
```

- 数字是主数字，取整显示（例如 `86K`、`1.2M`，和统计页的 token 写法一致）；还没算出来时只写“今天”。
- 设了线并且已越线：数字变成提醒色，读屏标签里说“已超过你设的 N”。
- 读屏标签写全：“今天，新输入加输出 1,234,567 token”。
- 点它打开统计页，并滚到“今天”区块。

### 4.2 统计页顶上的“今天”区块

统计页最上面、范围选择之上，一个不随范围、来源、项目筛选变化的区块：

```
今天（截至 14:32，数字最多晚 30 秒）
新输入 + 输出   1.2M        过去 7 天同一时刻平均 0.9M
缓存读取        18.4M
轮数 37 · 工作时长 2 小时 10 分
提醒线：2M（已用 60%）   [修改]

来源          新输入+输出   缓存读取   轮数   工作时长
Claude Code   1.0M         17.9M      25     1 小时 40 分
Codex         0.2M         0.5M       9      25 分
Cursor        —            —          3      5 分
```

- 设了线时显示“提醒线：N（已用 x%）”；越线时写“已超过”并用提醒色；没设线写“没有设提醒线”。“修改”跳到通知设置里的这一项。
- 没有任何轮次时写“今天还没有用过”。
- 主数字为“—”时（今天的来源都没有 token 数据）写明原因。

### 4.3 设置

放在通知设置里，作为一种通知（与“权限确认”“一轮结束”等并列）：

- 两样东西，各管各的（实现时的决定）：
  - **提醒线**：一个数，空着（或 0）就是“没有设提醒线”。设了线，顶栏变色和统计页区块就按它显示，**和任何开关无关**。所以设置页里这个输入框不随通知总开关变灰。
  - **“越线时发桌面通知”开关**：和其他通知种类一样，受通知总开关管。
- 单位由实现定，页面上要写清（例如以“万 token”输入）。
- 线存在服务端（和其他通知设置同一处），不只存在浏览器里，换浏览器也一样。

## 5. 提醒

- 服务端在每次重算“今天”之后判断：主数字从“没到线”变成“到了或超过线”，且这一天、这条线还没提醒过，就发一次桌面通知：“今天的新输入 + 输出已超过 N（现在 M）”。
- 只有**用量增长造成的越线**才提醒，而且只在当时能发的情况下发；别的情况只变色，不补发（实现时的决定，和通知引擎对“异常”类通知的做法一致：开关打开之前出现的不发）。具体：
  - 越线时总开关或这一项关着：不发；同一天后来打开了也不补发。
  - 设线或把线改低时，今天已经超过新线：不发（用户正看着页面，变色就够了）；线改高之后今天又涨过新线，发一次。
  - 服务刚启动、重新导入、重建数据库时，启动期间的工作做完之前看到的越线不发（顶栏照常变色）；服务关着时用过了线，开机后不补发。
- 判断方法：服务端记住“今天、这条线，已经处于越线状态”（不论当时发没发通知），存在 meta 里；只有从“没越线”变成“越线”的那一次重算、并且当时开关都开着、启动工作已完成，才发。同一天同一条线因此最多一次，重启后不重复。过零点清零。
- 通知点开去统计页的“今天”区块。
- 通知文字不含任何会话内容。

## 6. 计算和推送

- 服务端一个“今天”服务：
  - 从统计页同一个会话摘要缓存取数（`SessionSummaryCache`，和统计、文件服务共享读取）。只取最后活动时间在过去 8 天之内的会话（今天 + 7 天对照），其余不读。
  - 有会话变化时标记需要重算，最多每 30 秒重算一次；没有变化不重算。过本地零点时重算一次。进行中的轮次的工作时长随时间增长，所以有进行中的轮次时，每 30 秒也重算一次（只用缓存里的摘要，不重读会话）。
  - 结果通过网页已有的全局会话订阅推送（和待处理页的 `attention` 消息同一条连接），新增一种消息；另有一个读取接口给第一次打开和重连时用。
- 统计页本身的接口和数字不变。

## 7. 边界情况

- 一个来源今天有 token，另一个没有：主数字只是有数据的来源之和，区块里写“Cursor、豆包没有 token 数据，不在这个数里”。
- Copilot CLI：只在退出时记总数，所以它今天的 token 要等会话退出才出现；手册写明。
- 时间读不出的记录不计入（和统计页一样）。
- 服务一整天没开：开机后顶栏照样显示今天用了多少（从已采集的数据算），但不补发通知。
- 系统时区或时钟变化：按服务当时的本地日期算；不做特别处理。

## 8. 文档

手册新增一节：顶栏“今天”的数字是什么、为什么不含缓存读取、一轮算在开始那天、最多晚 30 秒、提醒线怎么设、什么时候提醒、什么时候不提醒（启动期间、历史）、哪些工具没有 token。

## 9. 测试要点

| 方面 | 要测的 |
|---|---|
| 口径 | 和统计页同一天的数字逐项相等（主数字、缓存读取、轮数、工作时长、按来源，“—”和 0 的区分也一样）；跨零点的一轮算昨天；退出时记账的记录按自己的时间；读不出时间的不算 |
| 对照 | 同一时刻平均：只算各天同一钟点之前开始的轮次；7 天里有空的日子算 0 |
| 提醒 | 用量涨过线发一次；同一天同一条线不再发；改高后再涨过新线再发；设线或改低到已超过时不发、只变色；越线时开关关着、后来打开不补发；过零点重置；重启后不重发；启动期间、导入、重建不发；没有 token 数据时不判断 |
| 推送 | 有变化 30 秒内更新；没变化不重算；过零点更新；页面断线重连后拿到最新 |
| 页面 | 顶栏数字和标签、越线变色、点击跳到区块；区块各行、空状态、“—”的说明；设置的保存和校验 |
| 性能 | 一个正在跑的 10 万节点会话：重算节流生效，采集不被拖慢 |

## 10. 留给实现的

- 数字缩写的具体写法沿用统计页已有的格式函数。
- 提醒线输入的单位和上限。
- 新的推送消息和接口的名字、字段。
- 通知设置字段名（沿用 `NotificationSettings` 的校验和“未知字段忽略、缺的取默认”的读取规则）。
