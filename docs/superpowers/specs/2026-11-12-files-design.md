# 按文件看 设计规格

- 日期：2026-11-12
- 状态：待评审
- 前置：主规格 `2026-11-10-agent-canvas-design.md`。本文只写新增的部分。

## 1. 目标

现在只能按时间顺序看一个会话做了什么。这一项加一个按文件的视角，回答两类问题：

- **这个会话动了哪些文件**：读过哪些、改过哪些，每个文件是在哪几步被动的。
- **这个文件被谁动过**：某个文件被哪些会话（哪个工具）读过、改过，最近一次是什么时候。

### 成功标准

- 会话页能列出这个会话读过、改过、新建、删除的文件，点一个文件能看到涉及它的每一步，点某一步在画布上选中它。
- 有一个跨会话的文件页，能按项目浏览、按路径搜索文件，看到动过它的会话，并跳到那个会话里对应的文件。
- 三种来源都支持；某个来源拿不到某类信息时如实说明，不猜。
- 本机真实数据量下（约 12 万次工具调用），文件页首次打开 3 秒内，之后 1 秒内。
- 升级后自动重建一次，Claude Code 和 Codex 原有的行为不变。

### 不做

- **从命令行里猜文件**：`Bash`、`exec`、终端命令里出现的路径不解析（`cat a.txt`、`sed -i`、重定向等写法太多，猜错比不显示更糟）。唯一的例外是 Codex 的 `apply_patch`，它的格式是固定的。
- 文件内容的差异对比、历史版本。
- 搜索和列目录（`Grep`、`Glob` 等）：它们的目标是目录不是文件，不计入。

## 2. 本机事实（2026-11-12，只看结构和数量）

文件路径出现在这些地方，都是绝对路径：

| 来源 | 工具 | 路径字段 | 算作 | 本机次数 |
|---|---|---|---|---|
| Claude Code | `Read` | `file_path` | 读 | 1,698 |
| | `Edit` | `file_path` | 改 | 1,073 |
| | `Write` | `file_path` | 写入（新建或覆盖） | 794 |
| | `NotebookEdit` | `notebook_path` | 改 | 很少 |
| Cursor | `read_file_v2` | `targetFile` | 读 | 27,520 |
| | `edit_file_v2` | `relativeWorkspacePath`（名字叫相对，实际是绝对路径） | 改 | 17,221 |
| | `delete_file` | `relativeWorkspacePath` | 删除 | 70 |
| Codex | `apply_patch`（在 `exec` 等调用的正文里，以 `*** Begin Patch` 开头） | 每个 `*** Update File:` / `*** Add File:` / `*** Delete File:` 行 | 改 / 写入 / 删除 | 584 次调用，885 个文件 |
| | `FileChange` 条目 | `changes` 的键 | 改 | 588 |

Codex 读文件靠的是命令行（`cat`、`rg` 等），没有结构化的记录，所以 **Codex 只有改动，没有“读”**。

## 3. 数据模型

节点增加一个可选字段：

```
files?: { path: string; action: 'read' | 'edit' | 'write' | 'delete' }[]
```

- 由各来源的归一化器在生成工具节点时填上；不涉及文件的节点没有这个字段。
- `path` 是规整后的绝对路径：分隔符统一成 `/`，Windows 盘符大写，去掉 `.` 和 `..`。相对路径按会话的工作目录补成绝对路径；补不出来的原样保留。
- 同一个节点里同一个（路径，动作）只记一次；一个节点最多记 50 个文件，超出的丢弃并在节点上标记“还有更多”。
- 只存路径和动作，不存文件内容。
- Codex 的 `apply_patch` 和紧随其后的 `FileChange` 条目描述的是同一次改动：同一个调用里两者都有时合并去重，不重复计数。
- `NORMALIZER_VERSION` 递增，升级后自动重建。

## 4. 会话页：这个会话动了哪些文件

会话页顶栏加一个“文件”按钮，打开右侧的文件面板（和现有的详情抽屉同一位置，二者同时只显示一个）。

- **文件列表**：这个会话涉及的每个文件一行，显示相对于会话工作目录的路径（在工作目录之外的显示完整路径）、读了几次、改了几次（改、写入、删除合计，并用小标记区分有没有新建或删除）、最近一次的时间。默认按“改动次数降序，再按最近时间”，可以切换成按路径排序；顶部有一个过滤框，按路径包含的文字过滤。
- **只看改过的**：一个开关，默认打开时只列被改动过的文件（读过但没改的通常很多）。
- **点一个文件**：展开它涉及的每一步，按时间排列，每步显示动作、工具名、时间、成败、是不是子代理做的。点某一步在画布上选中并定位到那个节点（概览视角下定位到它所在的轮次卡片，并在下方瀑布图里选中这一步）。
- 子代理内部动的文件计入会话。
- 面板底部一行小字说明：只统计读写文件的专用工具，命令行里的文件操作不在内；Codex 只有改动没有读。

会话页的地址支持直接打开某个文件：`#/s/<会话 id>/f/<路径>`，打开时面板自动展开到那个文件。

## 5. 文件页：这个文件被谁动过

顶栏加“文件”入口，页面 `#/files`。

- **筛选条**：项目（必选一个，默认上次选的，没有则第一个）、来源、时间范围（7 天 / 30 天 / 全部）、“只看改过的”、路径过滤框。
- **文件列表**：所选项目下被动过的文件，每个一行：相对于项目目录的路径、动过它的会话数、读 / 改的总次数、最近一次的时间和来源。默认按最近时间降序，可按改动次数或路径排序。一次最多显示 200 个，多出的提示用过滤框缩小范围。
- **点一个文件**：展开动过它的会话，每个会话一行：来源标记、会话标题、读 / 改次数、最近一次的时间；点击跳到 `#/s/<会话 id>/f/<路径>`。
- 一个文件属于哪个项目：按动它的那个会话所在的项目算（同一个文件被两个项目的会话动过，就在两个项目下各出现一次）。
- 加载中、失败、没有数据三种状态。

## 6. 接口与计算

- `GET /api/sessions/:id/files`：这个会话的文件列表（路径、各动作次数、首次和最近时间）及每个文件涉及的节点（节点 id、动作、工具名、时间、状态、是否子代理）。会话页的面板用它；数据从该会话的节点算出。
- `GET /api/files?projectId=&origin=&range=&changedOnly=&q=&sort=&limit=`：所选项目的文件列表及每个文件的会话明细（会话 id、来源、标题、次数、最近时间）。
- 两个接口只返回路径、计数、时间、名字和 id，不含对话内容。和其他接口一样只接受本机请求。
- 计算方式沿用统计页的做法：每个会话一份“文件小结”，缓存在内存里，会话变了才重算；汇总时按筛选条件合并。服务启动完成后在后台预热。路径比较在 Windows 上不分大小写。

## 7. 各来源能给出什么

| | Claude Code | Codex | Cursor |
|---|---|---|---|
| 读 | ✅ | ❌ 没有记录 | ✅ |
| 改 | ✅ | ✅（`apply_patch`、`FileChange`） | ✅ |
| 新建 | ⚠️ `Write` 分不清新建还是覆盖，统一显示为“写入” | ✅ `Add File` | ⚠️ 分不清，算作“改” |
| 删除 | ❌ 没有专用工具 | ✅ | ✅ |
| 命令行里的文件操作 | ❌ | ❌（除 `apply_patch`） | ❌ |

## 8. 错误处理

- 路径字段缺失、不是字符串、是空串：这个节点不记文件，不报错。
- `apply_patch` 正文被截断（存的输入有 64 KB 上限）：只取能完整读到的文件行。
- 单个会话的小结计算失败：跳过它并计数，其他照常。
- 接口参数不合法：400；未知的项目：空结果。

## 9. 测试

- 归一化器：三种来源各自的合成记录，覆盖第 2 节每一行、路径规整（分隔符、盘符、`..`、相对路径）、去重、50 个上限、`apply_patch` 与 `FileChange` 合并、被截断的补丁；重放结果与实时一致。
- 小结与汇总：用合成的图验证计数、子代理内部的文件、项目归属、筛选、排序、大小写。
- 接口：参数校验、返回里不含对话内容。
- 页面：纯函数（相对路径显示、排序、过滤、地址的解析与生成）有单元测试；实际观感在浏览器里核对。
- 真实数据：核对各来源各动作的总次数与第 2 节的数量一致。
